# 실환경 트리거링 테스트 가이드

[TEST-CASES.md](TEST-CASES.md) §1의 트리거링 테스트를 **실제 Claude Code 환경**에서 돌리기 위한
절차서다. 케이스 원본은 TEST-CASES §1이며, 이 문서와 어긋나면 그쪽이 기준이다.

무엇을 검증하나: 스킬의 frontmatter description만 보고 Claude가 **스킬을 자동 로드하는지**.
실행 결과가 아니라 **로드 여부**만 판정한다.

## 준비 (다른 로컬에서)

```bash
git clone https://github.com/whysowlee/commerce-browser-skill.git
cp -r commerce-browser-skill/commerce-research ~/.claude/skills/   # 개인 스킬로 설치
```

설치 확인: Claude Code 새 대화에서 `/skills` 또는 스킬 목록에 `commerce-research`가 보이면 된다.
(Claude.ai에서 하려면 `./package.sh`로 zip을 만들어 Settings > Capabilities > Skills에 업로드.)

## 절차 — 케이스마다 반복

1. **새 대화를 연다.** 같은 대화에서 여러 케이스를 돌리면 이전 맥락이 판정을 오염시킨다.
2. 아래 표의 문구를 **한 글자도 바꾸지 말고** 그대로 입력한다.
   ("실행하지 말고" 같은 말을 덧붙이면 트리거 판정 자체가 달라진다.)
3. 스킬이 로드되는지만 확인하고 **즉시 ESC로 중단한다.**
   그대로 두면 실제 수집이 시작된다 — 특히 T4는 규모 협의, T11은 스케줄 등록까지 간다.
4. 결과를 기록한다: 로드됨 O / 안 됨 X.

## 판정 기준

- 전체: should-trigger **≥10/11**, should-not **0/6**
- 스토리3(T7·T8·T9·T11)을 뺄 경우: should-trigger **≥6/7** 기준으로 기록하고
  뺐다는 사실을 결과에 명시한다. (트리거 판정 자체는 스냅샷 데이터가 없어도 되므로
  스토리3 케이스도 다른 로컬에서 돌릴 수 있다 — 로드 확인 후 중단하면 된다.)

## 결과 기록

표에 O/X를 채워 공유하거나, TEST-CASES.md 체크리스트의
"트리거링 — 실환경 검증" 항목에 결과·일시·환경(기기/Claude Code 버전)을 적는다.
실패 케이스는 문구·응답 요약을 함께 남긴다 — description 보강의 재료가 된다.

참고: 같은 케이스들의 프록시(시뮬레이션) 결과는 11/11·0/6이었다 (2026-07-29, v1.2.0).
실환경 결과가 이보다 나쁘면 프록시가 못 잡는 요인(스킬 목록 경쟁, 하네스 차이)이 있는 것이니
실패 케이스를 그대로 기록해 달라.
