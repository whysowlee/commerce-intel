## 2. 완주(happy path) 기준

### 2-1. intel 파이프라인 완주 (v11 신설 — E2E 기준)

한 번의 수집 요청이 다음을 전부 거쳐야 완주다. 통과 기준은 SPEC-INTEL §7.

```
재사용 판정(check) → 수집(플랫폼 스킬) → 검증(validate) → DB 적재(load)
→ 시트 미러(sync — 실패 시 보고 후 계속) → 리포트
```

- **같은 대상 2회째 요청**: 재사용 판정이 먼저 일어나고 스킵 여부·마지막 관측 시각이
  보고돼야 한다. 조용히 재수집하거나 조용히 옛 데이터를 쓰면 실패다.
- **미러 실패 시**: 수집·적재·리포트는 완주하고 "미러가 밀렸다"가 보고에 있어야 한다.

팀 커버리지(E-TC) 자동 검증은 **가짜 시트 객체**로 돈다 — 네트워크에 붙지 않는다는
기존 원칙 그대로다. 대신 `run_context` 매핑만은 실제 시트로 1회 실측했다(2026-08-03,
1,206행 → 24/24 일치) — 매핑이 틀리면 조회가 조용히 0건을 돌려주고, 그건 "중복 없음"과
구분되지 않기 때문이다.

자동 회귀의 한계: 대시보드의 실제 상호작용(필터→전 차트 갱신, 호버, 클릭)은 인라인
JS라 정적 검사로는 훅 존재까지만 본다. 렌더는 브라우저로 확인한다(2026-07-31 실측:
라이트 모드 전 섹션 렌더·콘솔 에러 0, 로그 스케일 0값 결함 발견·수정).
