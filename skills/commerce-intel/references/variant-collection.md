# 옵션(컬러·사이즈) 수집 — 라인시트 심화

상품 단위 라인시트를 **옵션(SKU) 단위**로 내린다. SPEC-INTEL §6의 실행 절차다.
얻으려는 것은 셋이다: **옵션 구성** · **옵션별 재고** · **옵션별 판매수량**.

## 0. 시작 전 판단 — 어디까지 갈지 먼저 정한다

| 단계 | 무엇을 | 언제 |
|---|---|---|
| **기본** | 옵션 구성 + 옵션별 품절 상태 (L1) | 옵션 요청이 있으면 라인시트 전체에 적용 |
| **심화** | 옵션별 재고 수량 (L2→L3) | **지정 상품 또는 상위 N개에만.** 예상 요청 수·소요를 보고하고 승인받은 뒤 (범위 승인 — L3 사용 자체는 D18로 승인 불요) |
| **추이** | 옵션별 판매수량 | 재고 관측이 2회 이상 축적된 뒤에만 (§4) |

**심화를 묻지 않고 시작하지 않는다.** 비용 공식을 계산해 보여준다:
`상품 수 × 옵션 수 × log2(상한 N) × 요청 간격`. 예: 상품 20 × 옵션 15 × 7회 × 2초 ≈ 70분.

## 1. 재고 프로브 계층 — 위에서부터, 얻히면 멈춘다

### L1 — 무료 (상태 변경 없음, 승인 불요)

이미 응답에 들어 있는 옵션별 품절 상태를 읽는다. **대부분의 요구는 여기서 끝난다.**

| 플랫폼 | 어디에 | 무엇을 주나 |
|---|---|---|
| 자사몰(Cafe24) | 상세 JSON-LD `offers[]` | 사이즈별 `availability`(InStock/OutOfStock). **혼재는 판매중이다** |
| 무신사 | 상품 상세 `goodsOption` | 옵션 구성. `isSoonOutOfStock`(품절임박)·`isRestock`도 상품 단위로 온다 |
| 29CM | 옵션 응답 · 리뷰 `optionValue`(`[COLOR:SIZE]IVORY:S_01`) | 옵션 축 이름과 값의 형식 |

수량은 안 나온다 — **재고 유무만 필요하면 여기서 끝내고 프로브로 내려가지 않는다.**

### L2 — 읽기 전용 프로브 (상태 변경 없음, 승인 불요)

PDP나 옵션 API에 **수량을 실어 사이트가 돌려주는 검증 응답을 읽는다.** 장바구니에
담지 않는다. 사이트가 흔히 주는 신호:

- "최대 N개까지 구매 가능합니다" / "재고가 부족합니다(남은 수량 N)" 같은 안내 문구
- 옵션 선택 응답의 재고 필드(사이트에 따라 노출)
- 수량 입력 UI의 `max` 속성

**이 층에서 정확한 수량이 나오면 프로브를 끝낸다.** 어느 신호로 얻었는지를
`meta.notes`와 `stock_basis`에 남긴다.

### L3 — 상태 변경 프로브 (D18 개정 — 승인 불요, 보고 의무)

L2로 안 될 때. 장바구니 담기·수량 변경·**결제 페이지 진입까지** 허용된다 — 결제
페이지에 노출되는 재고·수량 정보도 읽을 수 있다. 승인은 필요 없지만 **무엇을 했고
되돌렸는지 보고서에 반드시 적는다.**

**지켜야 할 것 (하나라도 어기면 중단):**

1. **비로그인으로 한다.** 로그인이 필요하면 그 사이트는 L2까지다 — 실계정을 쓰지 않는다.
2. **담았으면 반드시 비운다.** 예외가 나도 비우기를 시도하고, 못 비웠으면
   `meta.notes`에 남기고 **사용자에게 즉시 보고**한다.
3. **실제 결제를 실행하지 않는다.** 결제 페이지 진입까지가 끝이다 — 주문 완료·결제
   수단 입력 제출은 절대 금지다(D18에서도 유지되는 유일한 상태 변경 금지).
4. **요청 간격을 일반 수집의 2배로** 한다(하한 2초) — 같은 상품에 연속 요청이 몰린다.
5. **차단(403/429/캡차)이 뜨면 프로브 전체를 중단**하고 거기까지의 결과로 보고한다.
   프로브는 차단을 유발하기 쉬운 성격이므로 더 보수적으로 멈춘다.

## 2. 이진 탐색 — 정확한 수량 찾기

상한 `N`(기본 100)까지 이진 탐색한다. 옵션당 약 `log2(N)`회(N=100이면 7회).

```
lo=1, hi=N
"N개 담기/검증" 성공 → stock_qty ≥ N → 상한 초과로 기록하고 멈춘다
이후 lo..hi 이진 탐색 → 성공하는 최대 수량이 stock_qty
```

- **상한 초과와 미상을 구분한다**: 상한을 넘으면 `stock_qty: null` +
  `stock_display: "100+"`. 아예 모르면 둘 다 `null`.
- 품절 옵션은 탐색하지 않는다(L1에서 이미 안다) — `stock_qty: 0`.
- 탐색 중 값이 흔들리면(같은 수량이 성공했다 실패) **실시간 재고 변동**이다 —
  마지막 관측을 쓰고 흔들린 사실을 notes에 남긴다.

## 3. 데이터 계약 — `variants[]`

상품 레코드의 **선택 필드**다. 없으면 기존 라인시트와 동일하다(하위 호환).

```json
"variants": [{
  "option_id": "4297589-BLACK-M",
  "option_name": "BLACK / M",
  "color": "BLACK", "size": "M",
  "sold_out": false,
  "stock_qty": 7, "stock_display": null,
  "stock_basis": "probe_read",
  "observed_at": "2026-07-31 14:00:00"
}]
```

| 필드 | 규칙 |
|---|---|
| `option_id` | 사이트가 주는 옵션 식별자. 없으면 `{product_id}-{정규화 option_name}` |
| `option_name` | **사이트가 준 원문**. 파싱 실패해도 이건 남는다 |
| `color`/`size` | 원문을 파싱해 담되, **축이 두 개가 아니면 `null`로 둔다** — 단일 옵션(사이즈만)·3축 이상(색·사이즈·기장)인 사이트가 있다. **없는 축을 지어내지 않는다** |
| `sold_out` | L1에서 온다. 항상 채워진다 |
| `stock_qty` | 정수. 상한 초과·미상은 `null` |
| `stock_display` | `"100+"` 같은 상한 표기, 또는 사이트 원문(`"재고 5개 미만"`) |
| `stock_basis` | `option_api`(L1) / `probe_read`(L2) / `probe_cart`(L3) / `unknown` |

- **`variants` 없음/`null` = 옵션을 수집하지 않았다.** 빈 배열 `[]` = 옵션이 없는 상품.
  둘을 구분한다.
- 옵션별 판매수량은 **담지 않는다** — 관측 감소분으로 계산한다(§4). 중복 저장하면
  관측과 어긋난다.

## 4. 옵션별 판매수량 = 재고 감소분

노출하는 사이트가 없으므로 **관측 두 개의 차이**로 얻는다(가격 변화 감지와 같은 성격).

- **관측 주기는 기존 랭킹 잡에 편승한다**(무신사 30분·29CM 1시간) — 별도 잡을 만들지
  않는다. 랭킹 스냅샷을 찍을 때 대상 상품의 옵션 재고를 함께 관측한다.
- `stock_qty`가 줄었으면 그 차이가 **최소 판매량**이다. 늘었으면 **재입고**이고 그
  구간의 판매량은 알 수 없다.
- **반드시 밝히는 한계 2개**: ① 재입고가 섞인 구간은 **과소 집계**된다(재입고 직전까지
  팔린 수량이 가려진다) ② 축적 전에는 값이 없다 — 첫 관측만으로는 `null`이다.
- 리포트 표기는 **"최소 판매량 N (관측 M시간, 재입고 K회 감지)"**이다.
  **"판매량"이라고만 쓰지 않는다** — 실제보다 작은 수를 진짜 판매량으로 읽는다.

## 5. 리포트에 실리는 것

- **옵션 매트릭스** — 행=컬러, 열=사이즈, 칸=재고(또는 품절 배지). 축이 두 개가 아닌
  상품은 목록으로 낸다.
- **사이즈/컬러별 집계** — 품절률, 재고 합, 최소 판매량. 브랜드의 사이즈 운영을 본다.
- **미수집 구분** — 프로브를 안 돌린 상품은 "미수집"이고 재고 0이 아니다. 빈칸으로
  두지 말고 명시한다(미수집 ≠ 품절 ≠ 재고 0).
- 프로브 층(`stock_basis`)을 각주로 밝힌다 — L1은 유무만, L2/L3만 수량이다.
