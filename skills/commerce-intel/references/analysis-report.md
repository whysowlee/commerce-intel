# 분석 리포트 — 가설 도출 도구 요구 스펙

`build_analysis_report.py`의 산출물 스펙이다(SPEC-INTEL §4). 이 리포트의 목적은 요약이
아니라 **사용자가 변인을 통제해 가며 스스로 가설을 만드는 것**이다. 요약 수치만 있는
리포트는 스펙 미달이다. 산출물은 외부 네트워크가 필요 없는 로컬 단일 HTML이다.

## 0. 리포트는 종류가 아니라 모듈의 조합이다 (D25 — 2026-08-03 사용자 지시)

전수조사·랭킹·라인시트를 **각각 별개 리포트로 뽑지 않는다.** 기능을 모듈로 갖고 있다가
필요한 것을 골라 **한 리포트**로 만든다. 같은 데이터를 여러 파일로 흩으면 조건을 바꿀
때마다 파일을 갈아타야 하고, 파일마다 필터 상태가 따로 놀아 비교가 안 된다.

```
python3 build_analysis_report.py --db data/intel.db --context "brand:로우클래식" \
    --modules kpi,linesheet,variants,scatter --out output/analysis-로우클래식.html
python3 build_analysis_report.py --list-modules     # 쓸 수 있는 모듈 목록
```

| 모듈 | 내용 | 데이터 조건 |
|---|---|---|
| `kpi` | n·중위 판매가·중위 할인율·품절·평균 옵션 품절률 | 항상 |
| `scatter` | 축 선택형 산점도 (X·Y·색 기준·로그) | 수치 축 1개 이상 |
| `dist` | 히스토그램 (중위선) | 수치 축 1개 이상 |
| `group` | 그룹별 박스 플롯 — 심슨의 역설 확인 장치 | 수치 축 1개 이상 |
| `variants` | 사이즈별 재고 (옵션 단위 품절률) | 옵션 관측 있음 |
| `timeseries` | 시계열 추이 (순위 반전·선 끊김·이동평균) | 시점 2개 이상 |
| `events` | 가격 변경 사건과 관측 창 증분 | 가격 변경 감지분 있음 |
| `linesheet` | 플랫폼 합집합 표 (입점·가격 차이) | 플랫폼 2개 이상 |
| `table` | 상품 표 (전 행) | 항상 |

- 기본은 `all`이다. **요청했지만 데이터가 없어 못 만든 모듈은 리포트에 적는다** —
  조용히 빠지면 독자는 그 분석을 *안 한 것*과 *못 한 것*을 구분하지 못한다.
- 생성된 리포트 안에서도 모듈을 켜고 끌 수 있다(상단 모듈 바). 데이터는 한 번만 심겨
  있으므로 껐다 켜도 다시 만들 필요가 없다.
- **모듈이 늘어도 조건 패널은 하나다** — 전 모듈이 같은 `filteredData`를 본다(§6).

## 0-1. 두 리포트의 조작 규약은 하나다 (D26 — `report_ui.py`)

스토리 리포트(`build_report.py`)와 이 대시보드는 데이터 출처가 다르지만 **읽는 사람이
배우는 규약은 하나여야 한다.** 팔레트·색 토큰·컴포넌트 CSS·툴팁·표 정렬·칩 필터·계층
묶어 보기·불리언 수식 컴파일러는 `scripts/report_ui.py`가 갖고 양쪽이 그대로 쓴다.

- 도움말은 전부 `data-tip`이다 — `title` 속성은 브라우저가 1초 넘게 기다렸다 띄워서
  "도움말이 안 뜬다"로 읽힌다.
- 필터 칩: 한 축 안에서 OR, 축끼리 AND, 건수 병기, 계층 카테고리는 대→중→소 캐스케이드.
- **수식 필터**: 값 이름을 `AND`·`OR`·`NOT`·괄호로 조합한다(`(무신사 OR 29CM) AND NOT 품절`).
  스토리 리포트의 입점 수식과 **같은 문법·같은 컴파일러**다. 대시보드는 상품의 값 집합
  (플랫폼·카테고리·핏·브랜드·프록시·품절)에 평가하고, 표기 이름과 원래 키를 둘 다 받는다.
- 표: 열 머리 정렬(값 없는 행은 방향 무관 뒤로) · 검색 · **묶어 보기**(대/중/소로 접어
  집계 행만 보고 필요한 것만 펼친다. 집계는 지금 조건을 통과한 행만 센다).

## 1. 변인통제 패널 (필수)

- 조건 축: 플랫폼 · 카테고리 · 핏(속성) · 브랜드 · 가격대(범위 슬라이더) · 품절 여부.
  DB에 있는 축만 노출한다 — 값이 전부 null인 축은 패널에서 뺀다.
- **모든 차트가 같은 필터를 공유한다.** 필터를 바꾸면 전 차트가 함께 갱신된다.
- **현재 조건과 표본 수(n)가 항상 화면에 보인다.** n이 작아진 채 결론을 읽는 사고를 막는다.
  n < 30이면 "표본이 작다" 경고를 차트 옆에 붙인다.

## 2. 축 선택형 산점도

- X·Y축을 수치 필드 중에서 드롭다운으로 고른다: 판매가 · 정가 · 할인율 · 하트 ·
  후기 수 · 평점 · 누적판매 · 실시간 보는 중 · 순위(있으면).
- 로그 스케일 토글(X·Y 각각). 하트·판매량은 몇 자릿수를 넘나들므로 기본 로그.
- 점 호버에 상품명·브랜드·가격·지표값, 클릭하면 상품 URL을 새 탭으로.
- **미노출(`null`)은 그리지 않는다** — 0으로 그리면 "반응 없음"으로 읽힌다.
  축 아래에 `제외 N건(미노출)`을 명시한다.
- **구간 표기에서 온 값(`view_count_display`만 있는 것)은 축으로 쓰지 않는다.**

## 3. feature 속성에 맞는 추가 그래프 (형태 개방 — D3)

축 2개 산점도가 전부가 아니다. 속성에 맞는 형태를 쓴다:

| feature 성격 | 형태 |
|---|---|
| 분포 비교 (가격대·평점) | 히스토그램 / 그룹별 박스 플롯 |
| 축적 관측이 있는 시변 값 | 시계열 — 가격 변경 시점 표시 + 전후 반응 증분 |
| 순위 | 순위 추이(순위권 밖 구간은 선을 끊는다) |
| 그룹 간 대조 (핏별·브랜드별) | 그룹 산점도 오버레이 또는 작은 배수(small multiples) |
| 옵션(사이즈)별 재고 | 가로 누적 막대 — 사이즈는 **자연 순서**로 세운다 |

### 3-1 사이즈별 재고 (`variants` 모듈)

`variants`·`variant_observations`에서 **옵션마다 마지막 관측**을 가져와 옵션 단위로 센다.

- 수집이 L1(사이트가 이미 준 품절 상태)까지만 돌면 `stock_qty`는 전부 `null`이다. 그때
  내는 것은 **옵션 개수 기준 품절률**이지 수량 비율이 아니고, 그 사실을 화면에 적는다.
- **옵션별 판매수량(§6-4 재고 감소분)은 수량 축적이 있어야 성립한다** — 없으면 계산하지
  않는다. "판매량"이라고 쓰면 실제보다 작은 수를 진짜 판매량으로 읽는다.
- 사이즈 문자열은 **사이트가 준 것 그대로**다. 표기가 다른 사이트를 한 이름으로 합치지
  않는다(없는 정규화를 만들지 않는다).
- 상품 축에는 `opt_total`·`opt_out_rate`(·수량이 있으면 `stock_sum`)가 붙어 산점도·박스
  플롯의 축과 그룹 기준으로 쓸 수 있다.

증분(하트 증분·판매 증분)은 같은 상품의 관측 2개 차이로만 계산한다 — 관측 창
(`from ~ to`)을 표기하고, 창이 다른 상품끼리의 증분 비교에는 경고를 붙인다.

## 4. 정직성 규칙 (전부 필수)

1. 헤더에 명시: **"이 도구는 가격-반응의 상관 탐색이지 엄밀한 가격 탄력성 추정이 아니다.
   상관은 인과가 아니다."**
2. 필터된 부분집합의 상관계수를 보여줄 수 있으나 "탐색용"임을 병기하고, n과 함께 낸다.
3. 축약 파싱 값(±4%)이 축에 쓰이면 각주로 밝힌다.
4. 미노출 제외 건수를 차트마다 밝힌다. 추정·보간은 어디에도 없다.
5. 데이터의 관측 시각 범위(collected_at min~max)를 헤더에 싣는다 — 시점이 섞인
   비교임을 숨기지 않는다.

### 해석 가드레일 (2026-07-31 차용 — anthropics/knowledge-work-plugins, Apache-2.0)

6. **심슨의 역설 경고.** 전체 집합에서 보이는 상관이 세그먼트(카테고리·핏·브랜드)로
   나누면 사라지거나 역전될 수 있다. 변인통제 패널이 정확히 이를 확인하는 장치임을
   리포트 안내문에 적고, **필터를 걸지 않은 전체 상관 옆에는 "세그먼트로 나눠
   확인하라"는 유도 문구를 붙인다.**
7. **생존편향 명시.** 이 데이터에 **없는 것**을 헤더에 적는다 — 내려간(판매 종료) 상품은
   수집 시점에 이미 없고, 순위권 밖은 관측 자체가 없으며(랭킹 축적), 품절 필터 상태에
   따라 품절 상품이 빠졌을 수 있다. "지금 팔리고 있는 것만 보고 성공 요인을 읽는"
   오류를 경고한다.
8. **다중비교 경고.** 축 조합을 바꿔 가며 탐색하면 우연한 상관이 반드시 나온다.
   "여러 조합을 훑다 발견한 패턴은 가설이지 결론이 아니다 — 새 데이터(다음 관측)로
   재확인하라"를 안내문에 넣는다.
9. **누적 지표는 증분으로.** `purchase_count`(누적판매)·하트 총량은 항상 증가하는
   값이라 시점 간 비교나 "요즘 반응"의 근거가 되지 않는다(허영 지표 문제).
   시점 비교 차트에서는 관측 간 **증분**을 쓰고, 횡단면 산점도에서 누적값을 쓸 때는
   "출시 오래된 상품이 유리한 값"임을 각주로 밝힌다.
10. **노이즈와 신호 구분.** 변화 강조는 기존 판정 기준(랭킹 길이의 10%·최소 3계단 등
    코드가 계산하는 임계)을 따르고, 임계 미만의 변동을 서사로 해석하지 않는다.
    변화 해석에는 관측된 사건(할인 시작/종료 — DB에 있는 사실)만 오버레이한다.
    시즌·행사 같은 외부 요인은 데이터에 없으므로 "가능성"으로만 언급한다.

## 5. 차트 선택·시각 규칙 (2026-07-31 차용 — data-visualization, Apache-2.0)

관계 → 형태 선택표(§3의 근거):

| 보여줄 것 | 기본 형태 | 비고 |
|---|---|---|
| 두 수치의 관계 | 산점도 (+3번째 변수는 점 크기) | 이 리포트의 주인공 |
| 분포 | 히스토그램 / 그룹 비교는 박스 | 평균·중위 선을 같이 긋는다 |
| 시간 추이 | 선 (순위권 밖 구간은 끊는다) | |
| 범주 비교·순위 | 가로 막대, 값으로 정렬 | 가나다순 정렬 금지(자연 순서 제외) |
| 그룹별 추이 비교 | 작은 배수(small multiples) | 패널 간 축 범위 통일 |

- **파이·도넛·3D는 쓰지 않는다.** 각도 비교는 사람이 못 한다 — 막대로 그린다.
- **막대는 0에서 시작한다**(아니면 차이가 과장된다). 선 차트는 변동 범위가 의미 있으면
  0이 아니어도 되지만 축 라벨을 명확히 한다.
- 이중축은 순위+가격 패널(기존 스토리 C 관례)처럼 필요한 곳에만, 양축 라벨 필수.
- **색만으로 계열을 구분하지 않는다**(적록색약 8%) — 선 스타일·직접 라벨 병용,
  기본 팔레트는 색약 안전 조합(파랑/주황 우선). 범주 색은 6개까지만.
- **제목은 데이터 이름이 아니라 발견을 쓴다** — 단 이 리포트는 가설 도구이므로
  단정형이 아니라 "…로 보인다(n=, 탐색용)" 형태로.
- 차트 장식(불필요한 격자·테두리·배경) 제거. 축 라벨과 단위는 생략 금지.

## 6. 대시보드 상호작용 규약 (2026-07-31 차용 — build-dashboard 구조, CDN 제외)

- **레이아웃**: 상단 헤더(제목+정직성 문구+필터) → KPI 카드 2~4개(n·중위 판매가·
  관측 범위 등) → 주 차트(산점도, 최대 면적) → 보조 차트 → 하단 상세 표(정렬 가능).
- **단일 파이프라인**: 필터 변경 → `filteredData` 하나를 다시 계산 → KPI·전 차트·표가
  전부 그 하나에서 다시 그린다. 차트별로 따로 필터링하지 않는다(불일치 원인).
- 필터 옵션은 하드코딩하지 않고 **데이터에서 유니크 값을 뽑아 생성**한다(건수 병기).
- 필터 갱신은 **애니메이션 없이 즉시** 다시 그린다.
- **성능**: 데이터 1,000행 초과면 차트용 사전 집계를 고려하되 **상세 표와 산점도는
  전 행 유지**(전 행 원칙 — 기존 리포트와 동일). 선 차트 계열당 ~500포인트 초과 시
  대표 시점 선별(평균 금지 — 기존 균등 구간 규칙).
- 표는 열 머리 클릭 정렬 + 중립 화살표 상시 표시, 값 없는 행은 방향 무관 뒤로
  (기존 리포트 관례 유지).

## 7. 구현 규약

- 데이터는 문서에 한 번만 심는다(`<script type="application/json">`) — 전 차트가 공유.
- 그리기는 인라인 JS/SVG — **외부 리소스 0.** build-dashboard의 Chart.js CDN 방식은
  이 원칙과 충돌해 채택하지 않는다(구조 패턴만 차용).
- 스토리 리포트(`build_report.py`)의 표·칩 UI 관례를 따른다: 필터 칩에 건수 표시,
  조용히 숨기지 않기, 값 없는 행은 정렬에서 뒤로.
- 공유 전 점검: 색 없이도 구분되는가 · 축·단위 라벨 있는가 · 데이터 출처와 관측
  범위가 적혀 있는가 · 흑백 인쇄에서도 읽히는가.

## 7-1. 시계열 뷰 (상시 — 축적 관측이 있을 때 자동 표시, 2026-07-31)

범용 대시보드에 **시계열 추이 패널**이 상시 붙는다. `build_analysis_report.py`가 그
context에 **시점 2개 이상 관측된 상품**이 있으면 자동으로 표시하고, 없으면(단일 스냅샷)
숨긴다. 랭킹 축적(모자 46시점 등)이 첫 소스다.

- 지표 전환(순위·판매가·하트·후기), 계열 수 조절, 이동평균 토글.
- **순위는 y축을 뒤집는다**(위=1위). **순위권 밖 구간은 선을 끊는다** — 이어 그으면
  없는 순위를 주장하는 것이다(기존 스토리 C 규칙 계승).
- 현재 변인통제 필터가 그대로 적용된다 — 필터 내 상품 중 관측 시점 많은 순 상위만 그린다.
- 시점 48개 초과면 균등 구간 대표 시점만(평균 금지). 페이로드 상한 120계열(초과는 건수 명시).
- **이동평균은 노이즈를 줄인 것이지 새 데이터가 아니다**를 안내문에 명시. 추세·변화점은
  관측된 사실(가격 변경 사건 패널)과 함께 읽는다 — 예측·외삽은 하지 않는다.

## 8. AI 자유 생성 모드 (D20 — 요청 특화 리포트의 기본)

사용자의 **특정 분석 요청**("핏별 가격대 분포 비교", "할인 전후 반응")에는 고정 대시보드
대신 **요청에 맞는 리포트를 AI가 직접 작성한다.** 범용 대시보드(`build_analysis_report.py`)는
빠른 탐색·기본형으로 유지된다.

절차 (순서 고정):

1. **데이터는 코드가 뽑는다** — `build_analysis_report.py --emit-json --out data/analysis.json`
   (필요하면 `--context`로 좁힘). **AI는 이 JSON을 `<script type="application/json">`으로
   그대로 임베드하고, 숫자를 손으로 옮겨 적지 않는다** — 표·차트·집계는 전부 임베드된
   데이터에서 인라인 JS가 계산한다.
2. **dataviz 스킬을 로드**하고 이 문서의 규칙(§1 변인통제·§4 가드레일·§5 시각 규칙·
   §6 상호작용)을 적용해 요청에 맞는 섹션 구성으로 HTML을 작성한다. 요청과 무관한
   섹션은 넣지 않아도 되지만 **정직성 요소는 요청과 무관하게 필수**다.
3. **린터를 통과시킨다** — `python3 scripts/lint_analysis_html.py <산출물>`.
   FAIL이 있으면 고치고 다시. **통과 전에는 완성으로 보고하지 않는다.**
4. **렌더를 확인한다** (dataviz 절차 7단계 — 브라우저로 열어 육안 확인).

린터가 강제하는 것: 정직성 배너·생존편향·다중비교 문구, 데이터 아일랜드(임베드 JSON),
외부 스크립트/스타일 0, 다크 모드, 구간 표기 축 금지. 린터가 못 잡는 것(막대 0 시작,
색약 안전, null≠0)은 §5·§4를 스스로 지켜야 하며 렌더 확인에서 본다.
