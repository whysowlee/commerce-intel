# 리포트 구성 (⚠️ 폐기됨 — D27)

> **이 문서는 현행 규범이 아니다.** HTML 산출은 **D27로 폐기**됐고 리포트는 PDF 2층으로
> 나간다 — 현행 스펙은 `insight-spec.md`다. `package.sh`가 이 문서와 `build_report.py`·
> `build_analysis_report.py`·`report_ui.py`·`lint_analysis_html.py`를 **배포에서 제외**한다.
>
> 저장소에 남아 있는 이유는 회귀 111건 중 82건이 그 생성기들의 HTML 출력으로 diff 규칙·
> 매칭·급등락 판정을 고정하고 있어서다. 테스트를 PDF·데이터 경로로 이식한 뒤 함께 삭제한다.
> **여기 적힌 것을 근거로 새 작업을 하지 마라.**

`build_report.py`가 만드는 HTML의 구조다. **코드 실행이 되는 환경이면 이 문서를 읽을 일이
거의 없다** — 스크립트가 알아서 만든다. 코드 없이 직접 써야 하거나, 리포트에 무엇이
들어가는지 확인할 때 읽는다.

직접 쓸 때는 `assets/report-template.html`을 복사해 채운다. 그 파일은 생성기가 직접
뽑아낸 것이라 클래스 이름과 스타일이 실제 리포트와 정확히 같다.

## 공통

리포트는 **외부 리소스를 하나도 부르지 않는 단일 HTML**이다. CSS와 JS가 파일 안에 들어
있고, 상품 이미지만 원본 URL을 링크한다(`referrerpolicy="no-referrer"`, 실패하면 회색
플레이스홀더로 바뀐다). 라이트·다크 모드를 둘 다 지원한다.

### 헤더

대상, 사이트, 수집 시각, 수집 항목 수, 지표 노출률, 그리고 **이 사이트가 안 주는 지표**를
따로 적는다. 무엇이 없는지 아는 것도 결과다.

### 경고 배너

문제가 있으면 헤더 바로 아래에 뜬다. 조용히 넘어가지 않는다.

| 배너 | 언제 | 뜻 |
|---|---|---|
| `banner-critical` 부분 수집 | `meta.incomplete: true` | 수집이 끝까지 안 갔다. 중단 사유를 함께 표시 |
| `banner-critical` 구조 변경 의심 | 필수 필드 결측 >30% | 어댑터 필드 매핑을 점검해야 한다 |
| `banner-warning` 결측률 초과 | 필수 필드 결측 >5% | 기준 미달이지만 리포트는 만든다 |
| `banner-warning` 총계 오차 | `source_total` 대비 ±5% 초과 | 수집이 온전하지 않다 |
| `banner-info` 비교 대상 부족 | 스냅샷 1개 | 변화 분석을 하지 않았다 |

### 값 표기 규칙

| 상황 | 표기 |
|---|---|
| 사이트가 안 주는 값 | `<span class="na">미노출</span>` — 숫자를 지어내지 않는다 |
| 구간으로만 주는 값 | `<span class="approx">300회 이상 (최근 1개월)</span>` — 문구 그대로 |
| 할인 중 | 판매가 굵게 + 정가 취소선 + 할인율 배지 |
| 품절 | 상품명 옆 `품절` 배지. 표에서 빼지 않는다 |

**구간 표기 값에는 정렬 키를 주지 않는다.** 정렬해도 뒤로 밀리고, 순위 차트에도 쓰지
않는다. 없는 정밀도로 순위를 매기면 리포트가 조용히 틀린다.

### 표

모든 표는 열 머리를 눌러 정렬하고, 상품명·브랜드로 거를 수 있다. 값이 없는 행은 정렬
방향과 무관하게 뒤로 간다. 수백 행이 되는 라인시트에서 이게 사실상의 열람 수단이다.

**묶어 보기**(2026-08-03 신설) — 카테고리를 `대분류`/`중분류`/`소분류`로 접는다. 접으면
품목마다 집계 행 하나만 남고(상품 수 · 중위가 · 반응 합), 행을 누르면 그 품목만 펼쳐진다.
집계는 **지금 필터를 통과한 행만** 센다 — 화면의 수와 표의 수가 다르면 그건 거짓말이다.
값이 없는 칸은 분모에서 빼고 `미노출 N`을 붙인다. 조작부는 분석 대시보드와 같은 것이다
(`report_ui.py`).

### 도움말

이름만으로 뜻이 안 통하는 열·조작부에는 `?` 또는 점선 밑줄이 붙고 **hover 즉시** 풀이가
뜬다. `title` 속성은 쓰지 않는다 — 브라우저가 1초 넘게 기다렸다 띄워서 "도움말이 없다"로
읽힌다. 전부 리포트 자체 툴팁(`data-tip`)이다.

### 차트

- 크기 비교는 **한 가지 색(파랑)** 가로 막대. 계열 색을 돌려쓰지 않는다
- 비교 항목이 **2개 이하면 막대그래프를 그리지 않고** 목록으로 낸다
- 순위 추이 선그래프는 **계열 5개까지**. 그 이상은 변동 폭이 큰 것만 그린다
- 미노출 지표는 **차트를 만들지 않는다.** 빈 차트를 두는 것보다 없는 게 정직하다
- 모든 마크에 hover 툴팁이 붙는다. 표가 접근성 대안이다

## 스토리 1 — 브랜드 라인시트 (멀티 플랫폼)

플랫폼 **1개면** 단일 라인시트, **2개 이상이면** 합집합 비교 리포트가 된다.
비교 레이어는 플랫폼이 2개 이상일 때만 만든다 — 1개면 비교 대상이 없다.

1. 헤더 — 플랫폼 목록, 사이트별 수집 건수와 단순 합, **합집합 상품 수와 입점 분해**
2. KPI — 수집 상품 / 할인 중(평균 할인율) / 품절(비율) / 후기 합계
3. **플랫폼 비교 요약** (2개 이상일 때) — 합집합·매칭 결과와 통합축 근거
4. **품목별 입점 차이** — 품목마다 양쪽 입점 / 한쪽 단독을 센 표(품목 · 합집합 ·
   양쪽 입점 · 사이트별 단독 · 양쪽 비율) + 사이트별 **단독 KPI**(건수 · 중위가 · 품목 수)
   와 **단독 판매가 분포**.
   구 `단독 입점 상품 성격` 섹션을 여기 합쳤다(2026-07-30) — 그 섹션의 품목 분포 막대가
   이 표의 `단독` 열과 **같은 값을 같은 순서로** 그리고 있었다(동점 tie-break만 달랐다).
   표를 그 열로 정렬하면 같은 답이므로 막대를 없앴고, 단독의 고유 정보인 **가격대**만 남겼다
5. **같은 상품 반응 강도 비교** — 매칭 상품만. 하트·후기를 품목 단위로 대조하고
   **기준 대비**(품목 배율 ÷ 전체 배율)를 같이 낸다
6. **가격·할인 포지셔닝 차이** — **집계만 낸다.** 품목별 평균 판매가 차이 막대 +
   "매칭 N개 중 판매가 같은 것 X개 / 다른 것 Y개" 요약.
   **상품별 대조 표는 두지 않는다** — 전 상품 표의 `가격 차이` 열이 그 표다(2026-07-30 통합)
7. **플랫폼별 품목 인기** — 사이트 **원본 카테고리** 기준 품목 성적표
   (상품 수 · 하트 합 · 상품당 하트 · 규모 대비 하트 · 후기 합 · 상품당 후기 ·
   규모 대비 후기 · 중위 가격 · 평균 할인율 · 후기가중 평점) + 막대
8. **전 상품** — 리포트에서 상품 목록이 나오는 **유일한 표**다
   - 플랫폼 1개: 이미지 · 상품명 · 브랜드 · 카테고리 · 가격 · 후기 · 평점 · 조회수 ·
     누적판매 · 좋아요
   - 플랫폼 2개 이상(합집합): 이미지 · 상품명 · **입점** · 브랜드 · **품목**(통합축) ·
     사이트별 가격 · **가격 차이** · 사이트별 후기·평점·좋아요
   - 필터 축: **판매**(기본 판매 중) · **가격**(판매가 다름/동일/비교 불가) ·
     **입점** · **품목**. 한 축에서 여러 개를 켜면 OR, 축끼리는 AND
   - 한쪽에만 있는 칸은 `—`다 — **미노출이 아니라 그 플랫폼에 그 상품이 없다는 뜻**이고,
     `가격 차이`도 같은 이유로 `비교 불가`다

**구 문장 폐기**: "같은 상품을 매칭하지 않는다"는 v6에서 뒤집혔다. 매칭은 범위 안이고
규칙은 **정규화 상품명 완전일치뿐**이다(유사도·가격 보조 매칭 금지 — 실측에서 정가까지
같은 다른 상품이 확인됐다). 매칭이 안 되는 상품은 실패가 아니라 **단독 입점 사실**이다.

**만들지 않는 것**: 플랫폼별 인기 상품 상위 10(막대·표). 전 상품 표를 좋아요로 정렬하면
같은 답이 나온다 — 같은 답을 두 번 그리지 않는다(2026-07-30).

## 스토리 2 — 시장 전수조사

**리뷰 본문은 수집하지 않는다.** 만족/불만족 판단 재료는 사이트가 노출한
후기 수·평균 평점뿐이고, 집계는 전부 `build_report.py`가 한다.
**분류 속성은 핏만 P0**(2026-07-29 확정) — 추가 속성(워싱 톤·기장·소재)은
사용자가 명시적으로 요청할 때만 넣는다.

1. 헤더 — `target`에 **좁힌 범위를 명시**한다("데님팬츠(남성)")
2. KPI — 상품 수 / 후기 합계(노출값 합산) / 중위 가격 / **평균 평점(후기 수 가중)** / 속성 분류율
3. **시장 요약** — 판매가 분포, **상품 평점 분포**(~2.9 / 3.0~3.4 / 3.5~3.9 / 4.0~4.4 / 4.5~,
   평점 미노출 상품은 제외하고 건수 명시), 속성(핏 등) 분포.
   섹션 각주에 "리뷰 본문은 수집하지 않는다"가 명시된다
4. **전 상품** — 기본 열 + 속성 열. **이미지 열은 없다** — 1만 행 규모에서도
   전 행을 한 파일로 유지하기 위한 결정이다(2026-07-29)

## 스토리 3 — 랭킹

### 스냅샷 1개일 때

1. 헤더 + `banner-info`(변화 분석 안 함)
2. KPI — 수집 순위 범위
3. **현재 랭킹** 표 — 순위 + 기본 열 + **보는 중 / 구매 중**(실시간 지표)

### 기간 diff일 때 (2026-07-30 재설계)

**스토리3의 모든 상품 표에는 이미지 열이 있다.**
구 구조는 섹션이 8개였는데 표 4개(신규 진입·이탈·순위 변동·가격 변화)가 열 구성이 거의
같았고, 그러면서도 **등장 상품 679개 중 158개(23%)만** 실렸다. 4개 섹션으로 줄이고
한 표에 전부 담는다.

1. 헤더 — 기간(절대 날짜), 스냅샷 개수, 사이트
2. KPI — 스냅샷 수 / **등장 상품 수** / **교체율** / 가격·할인 변화(시점 확정 수)
   - 신규 진입·이탈은 KPI에서 뺐다. 첫·마지막 두 시점만 비교한 값이라 기간이 길어지면
     실제 교체를 과소 표기한다. **교체율 = 인접 스냅샷 평균 신규 유입률**로 대체
3. **기간 개요** — 스냅샷 타임라인 스트립(점 하나 = 스냅샷, 부분 수집은 색 구분).
   33행 표는 접어 둔다
4. **상품별 추이** (주 표, 한 행 = 한 상품)
   - 이미지 · 상품명 · 브랜드
   - **끝점** — `유지` / `신규 진입` / `이탈` / `기간 중만`. 필터 축이다.
     **신규 진입·이탈 표를 따로 두지 않고 이 축으로 흡수한다**
   - **랭킹 체류** — `28/33회 · 85%`. `전 구간`/`일부 구간` 라벨을 대신한다.
     그 라벨은 "첫·마지막 스냅샷 둘 다에 있었나"라는 구현 사정을 말하는데
     읽는 사람은 "관측이 온전한가"로 읽었다 — 숫자가 라벨보다 정직하다
   - **순위 추이 스파크라인** — 순위권 밖 구간은 끊긴다. 순위 축은 **전 행이 같은 범위**라
     행끼리 모양을 비교할 수 있다
   - **순위 변동** ▲▼ (첫 관측 − 마지막 관측)
   - **가격 추이 스파크라인** — 상품마다 자기 가격 범위로 그린다(행끼리 높이 비교 금지).
     뒤에 깔린 띠가 할인 구간이다. 꼬리표는 관측된 최저~최고
   - **가격 변화** / **할인율 변화** / **감지된 변화 · 시점**(관측 창)
   - 필터 축 4개: 끝점 · 관측 · 순위 · 가격. **1회만 스친 상품은 기본에서 빼 두고**
     건수는 칩에 표시한다(조용히 숨기지 않는다)
   - 시점별 가격·할인 변화 원자료는 표 아래에 접어 둔다
5. **추이 차트** — **위 표의 현재 정렬·필터 순서대로 상위 N개**를 그린다.
   차트가 따로 선택 규칙을 갖지 않으므로 "왜 그 5개인지"를 설명할 필요가 없다
   - 계열 수는 **1~100**을 사용자가 입력한다
   - **5개까지는 겹쳐** 그린다(계열 색 5개, 상품끼리 비교)
   - **6개 이상은 나란히** 그린다(작은 배수 격자). 순위선 100개를 겹치면 읽을 수 없다 —
     색을 늘리지 않고 **형태를 바꾼다**
   - 나란히 보기의 각 칸 = **순위(좌축) · 가격(우축) · 할인 구간(배경 띠)** 한 좌표계.
     순위 축은 전 칸 공통, 가격은 상품별. 가격이 안 변한 상품은 선을 그리지 않고
     우축 라벨만 둔다(가운데 점선이 순위 그리드선과 혼동된다)
   - 표 행을 누르면 그 상품의 큰 패널이 펼쳐진다
   - 표식: 시점 확정 = 세로 점선 / 순위권 밖이던 구간에 걸친 변화 = **띠**.
     같은 축에 놓는 것이고 **인과를 주장하지 않는다**

**계열 데이터는 문서에 한 번만 심는다** (`<script id="series-data" type="application/json">`).
스파크라인·추이 차트·행 펼침 상세가 같은 데이터 하나를 쓴다. 모든 시점을 `null`까지 채우면
2만 칸이 되므로 **관측된 시점만** 담는다(33스냅샷·679상품 실측 3,300건 ≈ 190KB).
