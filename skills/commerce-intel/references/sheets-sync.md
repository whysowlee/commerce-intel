# 구글 시트 미러 절차

정본은 로컬 `data/intel.db`이고 시트는 **사람이 보고 공유하는 창구**다(단방향, SPEC-INTEL §3).

읽기 경로는 **하나뿐**이다 — `intel_db.py check --team`이 `runs` 탭을 조회해 팀원이 이미
수집했는지 본다(D32). 단방향 원칙은 그대로다: 읽은 값은 정본에 쓰지 않고 판정에만 쓴다.
쓰는 쪽(`sync_sheets.py`)과 읽는 쪽이 `open_spreadsheet`·`fetch_tab`을 공유한다.

## 실행

```bash
python3 scripts/sync_sheets.py     # DB 적재(load) 뒤에 호출한다
```

- `products`·`variants`·`platforms`·`runs`·`proxy_defs` 탭은 전체 다시 쓰기,
  `observations`·`variant_observations`·`proxy_cache` 탭은 rowid 기준 증분 append
  (`sync_state`가 진행점을 기억 — 중복 append 없음).
- **스토리별 뷰 탭 3개** — `뷰_라인시트`(brand:) · `뷰_전수조사`(market:) ·
  `뷰_랭킹`(ranking:). context 접두사로 걸러 **상품별 최신 관측**을 사람이 읽는 헤더로
  낸다. **context 열이 앞쪽(2열)에 있어** 스토리 안의 세부 대상(랭킹 카테고리·브랜드명)은
  시트 필터로 걸러 본다. **정본이 아니라 파생**이다 — 매 동기화마다 전체 다시 쓰기.
  전수조사 뷰에는 핏 열이 채워져 "시트가 재사용 가능한 DB"임을 눈으로 확인할 수 있다.
- **빈 탭은 만들지 않는다** — 데이터가 0행인 테이블·스토리는 탭을 생성하지 않고,
  이미 있으면 지운다(데이터가 생기는 순간 자동으로 등장한다). 빈 탭은 "확인 안 한 것"과
  "없는 것"을 구분 못 하게 만든다.
- **`안내` 탭이 시트의 지도다** — 단방향 미러 경고·동기화 시각에 더해 **스토리 현황**
  (라인시트/전수조사/랭킹별 행수 또는 "아직 데이터 없음")과 **탭 가이드**(탭마다 행수·
  무엇이 담겼는지·언제 생기는지)를 매 동기화마다 다시 쓴다.

## 종료 코드별 대응

| exit | 뜻 | 해야 할 일 |
|---|---|---|
| 0 | 미러 완료 | 없음 |
| 3 | 인증·설정 없음 (gspread 미설치 / 키 없음 / config 없음) | **수집·적재는 유효하다.** 사용자에게 "미러가 밀렸다 + docs/SHEETS-SETUP.md로 1회 설정 필요"를 보고하고 작업은 계속한다 |
| 1 | 동기화 실패 (권한·네트워크) | 같음 — 보고하고 계속. 다음 성공 때 sync_state부터 따라잡는다 |

**어떤 경우에도 미러 실패 때문에 수집·리포트를 멈추지 않는다.** 반대로 실패를 조용히
넘기지도 않는다 — 시트가 정본보다 뒤처져 있다는 사실을 사용자가 알아야 한다.

## 시트 수동 편집

시트에서 사람이 고친 값은 정본에 반영되지 않고 다음 미러에서 덮일 수 있다(전체 다시
쓰기 탭). 사용자가 "시트에서 고친 걸 반영해달라"고 하면 — 그 값을 정본에 넣는 절차가
아직 없음을 알리고, 무엇을 고치고 싶은지 받아 DB에 직접 반영한 뒤 다시 미러한다.

## 용량

시트 셀 한도는 1,000만이다. `observations`가 접근하면(수십만 행 규모) 연도별 탭 분리를
사용자에게 제안한다 — 정본은 로컬이므로 시트 분리는 데이터 손실이 아니다.
