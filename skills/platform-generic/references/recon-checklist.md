# 기술 정찰 체크리스트

처음 보는 커머스 플랫폼에서 수집을 계획하기 전에 확인할 것들이다.
platform-generic(수집 전 정찰)과 channel-scout 에이전트(입점처 보고서의 기술 정찰
섹션)가 같은 목록을 쓴다. **확인한 것과 못 한 것을 구분해 기록한다** — 「미검증」 표기.

## 0. 접근 정책 (제일 먼저)

- [ ] `robots.txt` — 무엇이 Disallow인가? 상품 목록·상세가 허용되는가?
  후기·게시판류가 막혀 있는가? (막혀 있으면 그 지표는 수집 불가로 기록 — 우회하지 않는다)
- [ ] 비로그인으로 목록·상세가 보이는가? 로그인 벽·연령 확인·지역 게이트가 있는가?
- [ ] 첫 요청들이 200인가? 403/캡차/봇 챌린지가 있으면 **정찰을 멈추고 그 사실을 기록**

## 1. 목록 데이터 경로 — 핵심 질문: 경로 A가 있는가

- [ ] 목록 화면을 열 때 **네트워크에 JSON 응답이 있는가?** (브라우저 도구의 네트워크
  기록으로 확인) 있으면 요청 URL·메서드·필수 파라미터·페이지 파라미터를 기록
- [ ] 그 JSON을 **화면 밖에서 직접 요청해도 200인가?** (서명·쿠키·헤더 의존 확인 —
  페이지 URL을 직접 조립하면 403인 사이트가 있다: 무신사 실측)
- [ ] 서버 HTML에 목록이 있는가, 껍데기(CSR)인가? — 원본 HTML로 판단한다.
  마크다운 변환기를 거치면 있는 데이터도 없어 보인다(29CM JSON-LD 실측)
- [ ] 구조화 데이터(JSON-LD·`__NEXT_DATA__` 류)가 있는가?

## 2. 규모·완전성 재료

- [ ] **총계가 노출되는가?** 화면(`24,686개`)이든 API(`totalCount`)든. 없으면
  `source_total = null`이 될 것이고 완전성 근거를 따로 세워야 한다
- [ ] 페이지네이션 방식: page 번호 / 커서 / 무한 스크롤? 끝은 어떻게 아는가
  (빈 페이지 · hasNext · 무증가)?
- [ ] 페이지당 몇 개? 페이지 크기를 키울 수 있는가(상한 확인)?
- [ ] **기본 필터 상태**: 품절이 기본 포함인가 제외인가? (총계가 필터의 함수다 —
  무신사 563 vs 2,022 실측. 이걸 모르면 완전성 검증 전체가 흔들린다)

## 3. 필드

- [ ] 계약 필드 대응: product_id · 이름 · URL · 이미지 · 브랜드 · 카테고리 ·
  정가/판매가/할인율 · 품절. **목록에 없는 필드는 어디에 있나**(상세? 별도 API?)
- [ ] **가격이 몇 개인가?** 여러 개면 화면 메인 판매가와 대조해 어느 것이
  "누구나 받는 가격"인지 확인 (개인화 가격 함정 — 29CM 55% 불일치 실측)
- [ ] 반응 지표(후기 수·평점·좋아요·조회수·판매량) 중 무엇이 노출되나?
  정수인가, 축약(`1.2천`)인가, 구간(`300회 이상`)인가?
- [ ] 평점 스케일(0~5? 0~100? 경로별로 다른가?)
- [ ] 인코딩: HTML에 charset 선언이 있는가? (없으면 UTF-8 명시 디코드 필요 — 무신사 실측)

## 4. 갱신 주기 (모니터링 대상이면)

- [ ] 랭킹·실시간 지표가 있는가? 갱신 주기 단서(updatedAt 필드·화면 표기)가 있는가?
  없으면 시차를 두고 두 번 받아 대조. 못 재면 「미검증」 — 스킵 창 24시간 기본

## 산출 형식

정찰 결과는 표로 정리한다: 항목 · 확인 결과 · 확인 방법(URL·응답 요지) · 일자.
확인 못 한 항목은 지우지 말고 「미검증」으로 남긴다 — 다음 정찰의 할 일 목록이다.
