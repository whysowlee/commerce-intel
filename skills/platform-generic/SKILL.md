# platform-generic

전용 스킬이 없는 플랫폼에서 **정찰 → 수집**을 한 번에 해낸다. 산출물은 다른 플랫폼
스킬과 똑같은 데이터 계약 JSON이다. 공통 규칙(속도·차단 중단·추정 금지·순회 상한)은
`commerce-intel` 오케스트레이터가 갖는다.

**이 스킬의 산출은 두 가지다**: ① 데이터 계약 JSON ② **실측 기록**(무엇이 동작했고
무엇이 함정이었나). ②는 이 플랫폼이 반복 대상이 될 때 `platform-skill-maker`의
입력이 된다 — 정찰하며 확인한 것을 그때그때 기록해 둔다(실측 일자 포함).

## 절차

### 1. 정찰한다

`references/recon-checklist.md`를 열고 항목대로 확인한다. 핵심 질문은 하나다 —
**"화면을 그릴 때 쓰는 JSON API(경로 A)가 있는가?"** 있으면 수집이 빠르고 안정적이다.

정찰 결과로 수집 계획을 세운다: 경로(A/B) · 목록 진입점 · 페이지네이션 방식 ·
총계 출처 · 종료 판정. **robots.txt가 막는 경로는 계획에서 뺀다.**

### 2. 규모를 확인하고 범위를 협의한다

첫 페이지에서 총계를 읽는다. 0건이면 중단 보고, 상한(오케스트레이터 규칙) 초과면
좁힐 축을 제시한다. **임의 샘플링 금지.**

### 3. 수집한다

- **경로 A가 있으면**: 확인된 요청을 그대로 반복한다. 파라미터를 바꿔 볼 때마다
  결과가 실제로 달라졌는지 확인한다(조용히 무시하는 사이트가 흔하다).
- **경로 B로 가면**: `references/common-traps.md`를 먼저 읽는다 — 다른 플랫폼들에서
  실측된 "조용히 틀리는" 함정 카탈로그다. 특히: 매 스크롤 스텝마다 수집(가상 스크롤),
  3연속 무증가 종료, 카드 = 고유 product_id 1개인 가장 가까운 조상, HTML 정규식
  파싱 금지, UTF-8 명시 디코드.
- 필드 매핑에서 확신 없는 값은 담지 않는다 — 특히 **가격이 여러 개면 화면 메인
  판매가와 대조**해서 고른다(개인화 가격 함정). 평점은 스케일을 확인해 5점으로 통일.
- 처음 보는 지표는 계약 필드에 억지로 욱여넣지 않는다 — 확실한 것만 담고 나머지는
  `meta.notes`에 관찰로 남긴다.

### 4. 검증·보고한다

수집 건수를 독립 총계와 대조해 나란히 보고한다(총계가 없으면 대체 근거 + 그 한계).
`meta.notes`에 정찰 요약(경로·근거·함정)을 남긴다 — 이것이 실측 기록의 최소본이다.

### 5. 반복 조짐이 보이면 스킬 승격을 제안한다

같은 플랫폼 요청이 반복되면 실측 기록을 입력으로 `platform-skill-maker`를 제안한다.
