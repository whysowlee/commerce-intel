# intel-explore — EDA 단

파이프라인 3단이다. **DB만 보고, 가설을 만들지 않는다.**

```
intel-collect → intel-store → [intel-explore] → intel-analyze → intel-insight
                  intel.db       signals[]
```

```bash
python3 ../commerce-intel/scripts/eda.py --db data/intel.db \
    --context "brand:로우클래식" --out data/eda.json
```

## 왜 기법이 고정인가

우리 도메인은 정해져 있다(패션 커머스 상품·관측). 매번 EDA를 새로 설계할 이유가 없고,
새로 설계하면 10분 SLA를 못 지킨다. 절차·임계값은 whysowlee/data-analytics-skills의
`programmatic-eda`에서 차용했고(2026-08-03), 결측 WARN 5%/FAIL 30%는 우리 데이터 계약이
이미 쓰던 값과 같아 그대로 맞물린다.

**실측 소요는 34,489건 전체가 6초다.** SLA 대비 여유가 크니 건너뛸 이유가 없다.

## 7종 — 무엇을 막는가

| # | 검사 | 막는 것 |
|---|---|---|
| 1 | 그레인 | 한 행이 무엇인지 못 박는다. 여기가 어긋나면 이후 전부가 어긋난다 |
| 2 | **결측 지도** | **미노출(`null`)과 0의 혼동.** 섞으면 "반응 없음"이라는 거짓말이 만들어진다 |
| 3 | 분포·이상치 | IQR 1.5배·\|z\|>3·왜도. **이상치를 지우지 않는다** — 히트 상품일 수 있다 |
| 4 | 축 카디널리티 | n<20 값으로 그룹 비교를 하는 것 |
| 5 | 상관 + **세그먼트 재확인** | 심슨의 역설 — 전체에서 보이던 관계가 쪼개면 뒤집히는 것 |
| 6 | 시계열 커버리지 | 시점이 없는데 "추이"라고 말하는 것 |
| 7 | **생존편향** | 데이터에 **없는 것**을 안 적는 것 |

## 산출물은 사람용 리포트가 아니다

`signals[]`는 **분석 단이 먹는 입력**이다 — "여기를 보면 뭔가 있을 수 있다"는 좌표이지
가설이 아니다. 실제 검정은 `intel-analyze`가 통계 플레이북으로 한다.

사람이 읽을 EDA 요약이 필요하면 상세 PDF에 실린다(`intel-insight`).

### 신호에서 빼는 것

- **정의상 연동된 쌍** — 할인율은 `1 − 판매가/정가`다. 셋의 상관은 데이터가 아니라
  **산수**이고, 넘기면 "할인율이 높을수록 판매가가 낮다"는 동어반복이 나온다
- **표본 미달 축** — 옵션이 7개 상품에만 붙었는데 신호를 내면 n=7짜리 가설이 만들어진다.
  축이 존재하는 것과 쓸 만한 것은 다르다

### 경고를 붙여 내보내는 것

- **허영 지표 쌍**(하트·후기 수·누적판매끼리) — 둘 다 시간에 따라 쌓이는 값이라 오래
  노출된 상품에서 동반 상승한다. 발견이 아니라 **노출 기간의 그림자**다

## 결과를 어떻게 읽나

- `small_sample: true` — n<20. 이후 모든 수치에 그 한계가 붙는다
- `nulls[].status == "FAIL"` — 결측 30% 초과. **그 축은 분석에 쓰지 않는다**
- `correlations[].simpson_flips` — 비어 있지 않으면 전체 상관을 믿으면 안 된다
- `timeseries.available == false` — 단일 스냅샷이다. "추이"·"변화"라는 말을 쓰지 않는다
- `survivorship.dropped_from_last_snapshot` — 마지막 관측에서 사라진 상품 수.
  이 데이터는 **살아남은 것만** 보고 있다

여기서 FAIL·경고가 나오면 **분석으로 넘어가기 전에 사용자에게 말한다.** 결측·표본·
생존편향을 모르고 낸 인사이트는 틀린 자신감을 준다.
