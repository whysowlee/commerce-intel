# platform-ownmall

자사몰에서 **화면에 노출된 값만** 모아 데이터 계약 JSON을 만든다. 무신사·29CM와 달리
**사이트가 하나가 아니다** — 브랜드마다 도메인이 다르고, 엔진(Cafe24·Shopify·고도몰 등)도
다르다. 이 스킬은 **엔진 무관 절차**를 갖고, 엔진별 수집 스킴은 `references/engine-*.md`로
분기한다(SPEC-INTEL D9). DB 적재·분석·리포트와 공통 규칙은 `commerce-intel`이 갖는다.

## 절차 — 도메인 확정 → 엔진 판별 → 분기

### 1. 도메인을 확정한다 (엔진 무관)

- 사용자가 URL을 줬으면 그대로 쓴다. 브랜드명만 말했으면 **검색으로 후보를 찾는다.**
  **도메인을 지어내지 마라** — `{브랜드}.co.kr` 추측이 대표적 실패다.
- 후보를 열어 **브랜드 진위를 확인한다**(타이틀·로고·푸터 상호). 후보가 여럿이거나
  애매하면 제시하고 사용자가 고르게 한다.
- 확정 도메인이 `meta.site` 값이다(`insilence.co.kr`). 찾은 경위를 `meta.notes`에 남긴다.

### 2. 엔진을 판별한다

`references/engine-detect.md`의 판별식을 순서대로 적용한다. 결과에 따라:

| 판별 결과 | 다음 |
|---|---|
| Cafe24 | `references/engine-cafe24.md` (실측 완료 어댑터) |
| Shopify | `references/engine-shopify.md` (**전 항목 미검증** — 실측하며 진행) |
| 그 외/판별 실패 | `references/engine-unknown.md` — platform-generic 정찰로 인계 |

**어느 경우에도 "비범위"로 거절하지 않는다.** 미검증 엔진이면 그 사실을 사용자에게
알리고 정찰부터 진행한다.

### 3. 수집한다 — 엔진 무관 원칙 + 엔진별 스킴

엔진과 무관하게 성립하는 것(이 스킬이 정한다):

- **robots.txt를 먼저 읽는다.** 스토어마다 다를 수 있다 — 막힌 경로는 우회하지 않는다.
- **전량은 카테고리 전수 순회 + `product_id` 중복 제거로 얻는다.** 브랜드 페이지
  하나로 끝나지 않고, `ALL`류 카테고리 하나로도 부족할 수 있다(Cafe24 실측: 23% 누락).
- **화면 총계가 없을 수 있다** — 그러면 `source_total`은 `null`이고, 완전성 근거를
  따로 세워 `meta.notes`에 적는다(예: "모든 카테고리 소진 + 각 카테고리 끝 도달").
  어느 카테고리에도 안 걸린 상품은 구조적으로 놓친다 — 이 한계도 함께 적는다.
- **반응 지표(후기·평점·좋아요·조회수·판매량)가 아예 없을 수 있다.** 없으면 전부
  `null`이고 리포트에 "미노출"로 나간다. robots가 후기 게시판을 막으면 **우회하지
  않는다.** 플랫폼 비교의 반응 강도 축에서 빠지고, 빠진 사실을 각주로 밝힌다.
- **품절 표시가 목록에 없을 수 있다** — 상세(구조화 데이터 등)로 판정하고, 무신사와
  비교할 때는 무신사를 품절 포함으로 맞춘다.

URL 패턴·페이지 종료 신호·필드 위치·품절 판정 위치는 전부 엔진별 문서가 정한다.
**한 엔진에서 잰 수치를 다른 엔진에 옮겨 적지 마라** — `ALL` 23% 누락은 Cafe24 실측이다.

### 4. 검증·보고

수집 건수와 완전성 근거를 보고한다. 새로 실측한 엔진 지식이 생겼으면 해당
`engine-*.md`에 실측 일자와 함께 추가할지 사용자에게 제안한다(반복 대상이면
`platform-skill-maker` 절차로).

## 옵션(컬러·사이즈) 수집 — L1 소스

Cafe24는 상세 JSON-LD `offers[]`가 **이미 사이즈별 재고 상태**를 준다(혼재 = 판매중,
engine-cafe24 §4). 다른 엔진은 「미검증」 — engine 문서에 실측을 쌓는다. 옵션별 수량이
필요하면 오케스트레이터의 `references/variant-collection.md` 프로브 계층을 따른다.
