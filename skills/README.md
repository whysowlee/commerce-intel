# commerce-intel 스킬 — 사용 안내

무신사·29CM·W컨셉·EQL·SSF·브랜드 자사몰에서 **상품과 랭킹 데이터를 모아 인사이트로
만들어 주는 Claude 스킬**이에요. 말로 시키면 알아서 모으고, 쌓아 두고, **검증된 가설을
PDF 리포트**로 만들어 드립니다.

명령어를 외우실 필요는 없어요. 평소 말하듯 하시면 됩니다.

## 1. 설치하기

> ### ⚠️ 웹사이트 Claude(claude.ai)에서는 동작하지 않아요
>
> 이 스킬은 **Claude Code**에서만 씁니다. 데스크톱 앱, 터미널(CLI), VS Code·JetBrains
> 확장 중 아무거나 좋아요. 브라우저로 claude.ai에 들어가서 쓰시면 안 됩니다.
>
> 브라우저에서 안 되는 이유는 이래요. 이 스킬이 하는 일은 대부분 **여러분 컴퓨터에서
> 일어나야 하는 일**이거든요.
>
> | 스킬이 하는 일 | claude.ai에서 |
> |---|---|
> | 파이썬 스크립트 실행(수집·분석·PDF 생성) | 안 됩니다 |
> | `data/intel.db`에 데이터 쌓기 | 안 됩니다 — 내 컴퓨터 파일이라서요 |
> | 랭킹을 주기적으로 자동 수집(crontab) | 안 됩니다 |
> | PDF 리포트를 `output/`에 저장 | 안 됩니다 |
>
> 그래서 claude.ai에 이 폴더를 올려도 **Claude가 파일을 읽어 설명은 해 주지만
> 실제로 수집하거나 리포트를 만들지는 못해요.** 설치는 아래대로 Claude Code에 해 주세요.

폴더를 Claude가 읽는 위치로 옮기면 끝이에요.

```bash
unzip commerce-intel-skills.zip

# 어디서나 쓰고 싶으실 때
cp -r skills/* ~/.claude/skills/

# 특정 프로젝트에서만 쓰고 싶으실 때
cp -r skills/* <프로젝트>/.claude/skills/
```

그다음 **새 대화**를 열면 인식됩니다. Python 3.9 이상과 **패키지 하나**가 필요해요.

```bash
python3 -m pip install reportlab      # 리포트 PDF를 만드는 데 씁니다
```

Claude가 웹 요청을 보낼 수 있어야 하고, 브라우저 제어 도구(Playwright MCP 등)가 있으면
더 잘 동작합니다.

### 설치되는 스킬

**어느 스킬을 부를지 고르실 필요는 없어요.** 말씀하시면 알맞은 단계로 알아서 넘어갑니다.

| 스킬 | 하는 일 |
|---|---|
| `commerce-intel` | **여기로 말을 겁니다.** 요청을 읽고 아래 단계로 넘겨요 |
| `intel-collect` | 사이트에서 모읍니다 |
| `intel-store` | DB에 넣고 시트에 올려요 · 팀원 것과 합칩니다 |
| `intel-explore` | 분석 전에 데이터 상태를 봅니다 |
| `intel-insight` | 검증된 가설을 PDF로 만들어요 |
| `platform-*` | 사이트별 수집 방법 (무신사·29CM·자사몰·W컨셉·그 외) |

### 설치가 됐는지 꼭 한 번 확인해 주세요

**스킬이 몇 개 빠져도 아무 에러가 안 납니다.** 그대로 쓰시면 "무신사에서 모아줘"가
그냥 안 되거나 엉뚱하게 동작해요 (2026-08-04에 실제로 7개가 조용히 빠진 적이 있어요).

아래를 그대로 붙여 넣어 주세요. **"빠짐:"이 하나도 안 나와야** 정상이에요.

```bash
for s in commerce-intel intel-collect intel-explore intel-fashion-md intel-insight \
         intel-store platform-29cm platform-eql platform-generic platform-musinsa \
         platform-musinsa-global platform-ownmall platform-skill-maker platform-ssf \
         platform-wconcept; do
  [ -f ~/.claude/skills/$s/SKILL.md ] || echo "빠짐: $s"
done; echo "확인 끝"
```

빠진 게 있으면 압축 파일을 다시 풀어서 덮어써 주시고, 그래도 안 되면 알려 주세요.
(프로젝트 폴더에만 설치하셨으면 위 경로의 `~/.claude`를 `<프로젝트>/.claude`로 바꿔서요.)

### 함께 오는 데이터 (한 번만 합치시면 됩니다)

빈 DB로 시작하지 않게 **일부 데이터를 같이 넣어 뒀어요.** 작업폴더에서 한 번 돌려 주세요.

```bash
python3 ~/.claude/skills/commerce-intel/scripts/intel_db.py merge \
    ~/.claude/skills/commerce-intel/assets/seed-intel.db
```

- **2000아카이브스 전 제품**(무신사·29CM·자사몰)과 **여성 데님팬츠 브랜드랭킹 상위30
  전수조사**가 들어 있어요. 상품 2,722개 · 관측 4,670건
- 핏·소재 같은 **AI 판정 결과도 같이** 와요 — 같은 판단을 다시 하지 않아도 됩니다
- 두 번 돌리셔도 안전해요(중복으로 쌓이지 않습니다). 이미 뭔가 모아 두셨어도 안전해요
- 그 밖의 데이터는 각자 모으시는 게 맞습니다 — **필요한 것만 골라 담았어요**

### 승인 창을 없애려면 (선택)

스킬이 스크립트를 돌릴 때마다 **"실행할까요?"** 창이 떠요. 매번 누르기 번거로우시면
아래를 `~/.claude/settings.json`(없으면 새로 만드세요)의 `permissions`에 넣어 주세요.

우리 스크립트 실행만 열어 두고 **그 밖의 명령은 그대로 물어봅니다.** 그래서 안전해요.

```json
{
  "permissions": {
    "allow": [
      "Bash(python3 ~/.claude/skills/commerce-intel/scripts/validate_data.py:*)",
      "Bash(python3 ~/.claude/skills/commerce-intel/scripts/eda.py:*)",
      "Bash(python3 ~/.claude/skills/commerce-intel/scripts/analyze.py:*)",
      "Bash(python3 ~/.claude/skills/commerce-intel/scripts/insight.py:*)",
      "Bash(python3 ~/.claude/skills/commerce-intel/scripts/sync_sheets.py:*)",
      "Bash(python3 ~/.claude/skills/commerce-intel/scripts/pdf_doc.py:*)",
      "Bash(python3 ~/.claude/skills/commerce-intel/scripts/diff_snapshots.py:*)",
      "Bash(python3 ~/.claude/skills/commerce-intel/scripts/group_variants.py:*)",
      "Bash(python3 ~/.claude/skills/commerce-intel/scripts/plan_sample.py:*)"
    ],
    "deny": [
      "Bash(python3 ~/.claude/skills/commerce-intel/scripts/intel_db.py:*)"
    ]
  }
}
```

- **`intel_db.py`는 일부러 막아 두었어요.** 데이터를 통째로 덮어쓰는 기능이 들어 있어서
  승인을 한 번 거치는 편이 안전합니다 (자주 쓰는 기능도 아니에요)
- 위 경로는 **`~/.claude/skills/`에 설치하셨을 때** 기준이에요. 다른 곳에 두셨으면
  경로를 그에 맞게 바꿔 주세요
- **안 넣으셔도 괜찮아요.** 동작에는 문제가 없고 승인 창만 매번 뜹니다

## 2. 시작하기

데이터가 쌓일 폴더를 하나 정하시고, 그 안에서 Claude를 열어 주세요.

```bash
mkdir -p ~/work/intel && cd ~/work/intel
```

첫 요청 때 필요한 준비는 스킬이 알아서 합니다. 결과물은 이렇게 쌓여요.

```
~/work/intel/
├── data/        모아 온 데이터가 쌓입니다 (지우지 마세요 — 다음에 다시 안 모으는 근거예요)
└── output/      리포트 PDF가 나옵니다 (더블클릭하면 열리고, 휴대폰으로 보내셔도 돼요)
```

### 팀에서 함께 쓰실 때 (꼭 읽어 주세요)

각자 자기 컴퓨터에 자기 데이터를 갖는 구조예요. 그래서 **두 가지만 지켜 주시면 됩니다.**

**첫째, 랭킹을 계속 모으는 건 한 분만 해 주세요.**

기록이 사라지지는 않아요. 다만 **시점이 불규칙하게 촘촘해집니다.**
두 분이 30분 주기로 모으시면 시각이 조금씩 어긋나서 이렇게 돼요.

```
A님   10:00        10:30        11:00
B님        10:07        10:37        11:07
      ↓
기록  10:00 10:07 10:30 10:37 11:00 11:07     ← 3회가 6개 시점으로
```

그러면 **간격이 7분·23분·7분…처럼 제멋대로가 됩니다.** 사이트는 30분마다 갱신하는데
7분 간격 구간에는 아무 변화가 없어서, "가격 내리고 반응이 얼마나 늘었나" 같은 걸 볼 때
빈 구간이 신호를 흐려요. 게다가 같은 데이터를 두 번 받아 오니 **사이트 요청도 두 배**라
차단 위험이 올라갑니다.

담당을 한 분 정해 두시고, 나머지 분들은 그 결과를 받아 쓰시면 됩니다.

**둘째, 같은 걸 여러 명이 동시에 모으지 말아 주세요.**
사이트에 부담이 가고, 막히면 팀 전체가 못 쓰게 돼요. 모으기 전에 팀에 한 번 물어보시는
편이 빠릅니다.

각자 모으신 데이터는 나중에 합칠 수 있어요 — 팀원 DB 파일을 받아서 **"합쳐줘"** 라고
말씀하시면 됩니다. 구조가 헷갈리시면 §6을 보시면 돼요.

## 3. 뭐라고 말하면 되나요

아래가 **실제로 되는 것 전부**예요. 표현은 자유롭게 하셔도 됩니다 — 뜻만 통하면 돼요.
**사이트 이름은 넣으셔도 되고 안 넣으셔도 됩니다.** 안 넣으시면 알아서 찾아 드려요.

### 저는 어디만 보면 되나요?

**전부 하실 필요 없어요.** 하시는 일에 따라 필요한 부분만 쓰시면 됩니다.

| 나는… | 보시면 되는 곳 | 데이터는 |
|---|---|---|
| **모으기만 해요** | 모으기 · 어디서 파는지 · 랭킹 쌓기 | 직접 모아서 시트에 올려요 |
| **결과만 봐요** (디자인·마케팅) | **분석·리포트**만 | 남이 모은 걸 받아 씁니다 (아래 참고) |
| **둘 다 해요** (MD) | 전부 | 모으고 바로 분석해요 |

**모으는 담당이 아니어도 분석은 하실 수 있어요.** 두 가지 방법이 있습니다.

1. **팀원 DB를 받으시면 돼요** — 파일을 받아서 *"팀원 DB 합쳐줘"* 라고 말씀하시면
   그때부터 내 것처럼 분석됩니다. 한 번 합쳐 두면 계속 쓰실 수 있어요
2. **리포트만 받으셔도 돼요** — 모으는 분이 만든 PDF를 받아 보시면 됩니다.
   이 경우엔 **스킬을 설치하실 필요도 없어요**

> 분석을 요청하셨는데 **"데이터가 없다"**고 하면, 아직 아무도 그걸 안 모은 거예요.
> 모으는 분께 요청하시거나 직접 모으시면 됩니다.

### 모으기

| 하고 싶은 것 | 이렇게 말씀하세요 |
|---|---|
| 브랜드 상품 전부 | "로우클래식 라인시트 수집해줘" · "인사일런스 상품 다 모아줘" |
| 한 사이트에서만 | "무신사에서 마뗑킴 상품 정리해줘" |
| 여러 사이트 비교 | "인사일런스 파는 데 전부에서 정리해줘" · "무신사랑 29CM 비교해줘" |
| 자사몰 포함 | "인사일런스 자사몰이랑 무신사 같이 봐줘" |
| 시장 전체 | "여성 로우라이즈 데님 전수조사해줘" · "무신사 데님팬츠 시장 조사" |
| 규모만 먼저 | "데님팬츠 몇 개나 있는지만 먼저 알려줘" |
| 표본으로 | "데님팬츠 표본으로 500개만 뽑아줘" (※ 말씀하셔야만 표본으로 해요) |
| 해외 랭킹 | "무신사 글로벌 홍콩 데님 랭킹 봐줘" (나라마다 랭킹이 달라요) |

### 어디서 파는지

| 하고 싶은 것 | 이렇게 말씀하세요 |
|---|---|
| 입점처 찾기 | "로우클래식 어디에 입점해 있어?" |
| 신규 채널 확인 | "이 브랜드 새로 들어간 데 있어?" |

### 랭킹 쌓기 (시계열)

| 하고 싶은 것 | 이렇게 말씀하세요 |
|---|---|
| 지금 한 번 | "29CM 여성슈즈 랭킹 지금 수집해줘" |
| 주기적으로 | "무신사 바지 랭킹 30분마다 오후 11시까지 모아줘" |
| 변화 보기 | "지난 24시간 순위 크게 오른 상품 보여줘" · "이번 주 신규 진입 뭐야?" |
| 기간별 순위 | "무신사 데님 이번 주 랭킹 봐줘" · "29CM 스커트 한 달 랭킹" |

**"이번 주·이번 달 랭킹"은 쌓아 둔 게 없어도 되는 곳이 있어요.** 무신사·29CM·EQL은
사이트가 기간별 순위를 그대로 주거든요. SSF·W컨셉·무신사 글로벌은 그 기능이 없어서
**우리가 모아 온 기간**만 볼 수 있습니다.

### 분석·리포트

**모으는 것과 별개예요.** 데이터만 있으면(직접 모으셨든 팀원 것을 합치셨든) 바로 됩니다.

| 하고 싶은 것 | 이렇게 말씀하세요 |
|---|---|
| 그냥 인사이트 | "로우클래식 인사이트 뽑아줘" · "데님팬츠 분석해줘" |
| 특정 축 | "핏별 가격대 비교해줘" · "할인율이랑 반응 관계 봐줘" |
| 할인 효과 | "할인 얼마 줬을 때 반응이 제일 좋았어?" |
| 플랫폼 비교 | "같은 상품인데 어디가 더 싸?" |
| 잘 팔리는 것 | "뭐가 빨리 품절나?" (재고 기록이 쌓여야 답이 나와요) |
| 자사 상품 | "우리 온고잉 상품들 반응 어때?" |
| 경쟁사 | "우리 브랜드랑 ○○ 비교해줘" |
| 이미지·이름 특성 | "착용컷인 상품이 더 잘 팔려?" · "영문 상품명이 반응이 나아?" |

**마지막 줄이 조금 특별해요.** 데이터에 없는 기준이면 AI가 **직접 판정 기준을 만들어서**
상품 이미지나 이름을 보고 분류한 뒤 검증합니다. *"썸네일에 따라 차이 있어?"* 처럼
막연하게 말씀하셔도 판정할 수 있는 항목들로 알아서 나눠요.
무엇을 어떤 기준으로 판정했는지는 리포트에 적어 드립니다.

### 상태 확인·관리

| 하고 싶은 것 | 이렇게 말씀하세요 |
|---|---|
| 뭐가 쌓였는지 | "지금까지 뭐 모았어?" · "DB에 뭐 있어?" |
| 시트에 올리기 | "구글 시트에 올려줘" |
| 팀원 데이터 합치기 | "팀원이 준 DB 합쳐줘" (파일 경로와 함께 말씀해 주세요) |
| 자사 상품 태깅 | "자사 상품 온고잉/시즌 태깅해줘" |

### 사이트를 말씀하지 않으시면

- **브랜드만 말씀하시면** — 어디서 파는지 먼저 찾아서 **판매처 목록과 규모, 예상 소요
  시간을 알려 드리고** 확인된 판매처를 **전부** 모읍니다. 입점처는 정해져 있는 사실이라
  따로 고르시라고 여쭤보지 않아요.
  (예를 들어 인사일런스는 이렇게 나와요 — 자사몰 · 무신사 남성/우먼 · 29CM 남성/우먼 ·
  W컨셉 · 지그재그)
- **카테고리만 말씀하시면** — 어느 사이트에 얼마나 있는지 **후보와 규모를 보여 드리고
  고르시게 합니다.** 상품군은 사실상 모든 사이트에 있어서 임의로 정하지 않아요.
- **사이트를 말씀하시면** — 말씀하신 곳만 모읍니다. 알아서 더 붙이지 않아요.

### 이런 요청은 받지 않아요

"쿠팡에서 노트북 최저가 찾아줘"(개인 쇼핑), "이 바지 대신 사줘"(구매 대행),
"크롤러 짜는 법 알려줘"(일반 코딩 질문). 시장 조사 도구이지 쇼핑 도구가 아니에요.

### 모으는 것과 분석하는 건 따로 하셔도 돼요

"모아줘"만 하시면 모아서 쌓아 두고 끝냅니다. 며칠 뒤에
**"아까 모은 걸로 핏별 가격 비교해줘"** 라고만 하셔도 돼요.
분석할 대상을 생략하시면 **직전에 모은 주제를 이어서** 해석합니다.
한 번에 둘 다 말씀하시면 이어서 진행해요.

말씀하시다가 범위를 바꾸셔도 됩니다 — **"무신사랑 바이모노만 수집해줘"**,
**"자사몰도 추가해줘"** 처럼요.

### 같은 걸 또 시키시면 다시 모으지 않아요

최근에 모은 게 있으면 **모으기를 건너뛰고 "언제 것을 썼는지" 알려 드려요.**
가격이나 순위처럼 자주 바뀌는 값은 몇십 분~하루, 옷의 핏처럼 잘 안 변하는 값은 석 달까지
재사용합니다.

**꼭 새로 받고 싶으시면 "다시 조사해" · "새로 받아" · "지금 수집해줘"** 라고 말씀해 주세요.

### 랭킹은 "지난달 것"을 가져올 수 없어요

과거 순위를 파는 곳이 없어서, **모으기 시작한 시점부터만** 쌓입니다.
그래서 "지난달 변화"를 보시려면 지난달에 모으기를 시작하셨어야 해요.

**"○○ 랭킹 계속 모아줘"** 라고 하시면 사이트 갱신 주기에 맞춰(무신사 30분·29CM 1시간)
자동으로 쌓기 시작합니다. **"11시까지만"** 처럼 기한을 주시면 그때 알아서 멈춰요.

## 4. 무엇이 나오나요

`output/` 폴더에 **PDF 두 개**가 나옵니다. 휴대폰에서도 그대로 열리고 남에게 보내셔도 돼요.

**인사이트 PDF** — 짧아요. 3~6쪽 정도이고, 매일 보시는 용도예요.

- **강한 주장 5개** — 아래 다섯 관문을 전부 통과한 것만 싣습니다
- **약한 단서 20개** — 통과하지 못한 것들이에요. 어느 관문을 왜 못 넘었는지,
  어떻게 다시 확인하면 되는지가 함께 적혀 있습니다
- 항목마다 **판매전략 / 디자인 / 마케팅** 딱지가 붙어 있어서 본인 것만 골라 읽으시면 돼요

**상세 PDF** — 길어요. 근거를 확인하실 때 여는 용도입니다.
인사이트의 각 항목이 "상세 12쪽"처럼 어디를 보시면 되는지 알려 드려요.

### 강한 주장이 5개보다 적게 나올 수 있어요

일부러 그렇게 만들었습니다. 관문을 통과한 게 3개면 3개만 내요 —
빈자리를 약한 것으로 채우면 "강한 주장"이라는 말이 아무 의미가 없어지니까요.

### 다섯 관문

1. **차이가 충분히 큰가** — 작은 차이는 발주 결정을 바꾸지 못해요
2. **표본이 충분한가** — 너무 적은 건수로는 판단하지 않습니다
3. **우연이 아닌가** — 가설을 많이 만들면 우연히 그럴듯한 게 반드시 나와요. 그걸 보정합니다
4. **쪼개도 유지되는가** — 전체에서 보이던 차이가 카테고리별로 나누면 뒤집히는 경우가 있어요
5. **다시 나오는가** — 데이터 절반으로 다시 확인해서 같은 방향이 나와야 합니다

### 이런 모양으로 나와요

> **[판매전략]** 플랫폼에서 lowclassic.com은 29CM보다 할인율이 낮다 (중앙값 0 대 18)
> *Cliff δ -0.67 · n=1,317 · p=0.000 · 홀드아웃 δ=-0.70*

숫자를 단정하지 않습니다. **"할인을 줄이세요"가 아니라 "이런 차이가 관측됐어요"** 로 써요.
판단은 사람이 하시는 겁니다.

리포트를 보시다가 더 궁금한 게 생기면 그냥 말씀하시면 돼요 —
"이거 브랜드별로 나눠서 다시 봐줘" 처럼요. 다시 모으지 않고 새로 만들어 드립니다.

## 5. 이런 건 하지 않아요

버그가 아니라 일부러 그렇게 만든 것들이에요. 틀린 숫자를 그럴듯하게 내놓는 것보다
낫다고 판단했습니다.

- **화면에 없는 값은 만들어내지 않아요.** 후기 수로 판매량을 역산하는 식의 추정은
  **요청하셔도 하지 않습니다.** 안 보이는 값은 리포트에 "미노출"로 표시돼요.
- **사이트가 막으면 멈춥니다.** 우회하지 않고, 거기까지 모은 걸로 리포트를 만들면서
  중단된 사실을 알려 드려요.
- **상품 이름이 완전히 같을 때만 같은 상품으로 봅니다.** 비슷한 이름을 묶지 않아요 —
  정가까지 똑같은 다른 상품이 실제로 있었거든요. 안 묶인 건
  **"이 사이트에만 있는 상품"** 이라는 정보가 됩니다.
- **여쭤보지 않고 상위 몇 개만 모으는 일은 없어요.** 양이 많아도 다 모읍니다.
  대신 **예상 소요 시간을 먼저 알려 드리니** 거기서 범위를 좁히시면 돼요.
- **로그인하지 않아요.** 로그인이 필요한 값이면 여쭤봅니다.
  **결제는 어떤 경우에도 하지 않아요.**
- **HTML 리포트는 만들지 않아요.** 산출물은 PDF뿐입니다. 조건을 바꿔 가며 들여다보는
  대시보드는 없앴고, 대신 **조건을 바꿔 보는 일을 도구가 미리 다 해서** 살아남은 것만
  실어 드려요.
- **W컨셉은 품절 정보를 가져올 수 없어요.** 목록에 품절 상품을 아예 싣지 않는 구조라
  "품절 아님"으로 채우면 사실과 달라집니다. 그래서 품절 칸을 비워 두고 그 사실을 밝혀요.
- **사이트마다 "1일·1주·1달 랭킹"을 줄 수 있는 곳과 아닌 곳이 갈려요.** 무신사·29CM·EQL은
  기간별 순위를 그 자리에서 받아올 수 있어서 **모아 둔 게 없어도** 답이 나옵니다.
  SSF·W컨셉·무신사 글로벌은 그런 기능이 없어서 **우리가 쌓아 온 기간**만 볼 수 있어요.

## 6. 데이터가 어디에 쌓이나요 (DB·시트 관계)

가장 헷갈리시는 부분이라, 여기만 읽으셔도 되도록 정리했어요.

### 한 줄 요약

> **데이터는 내 컴퓨터에 쌓이고, 시트는 그걸 남들도 보시라고 올려두는 곳이에요.**

### 그림으로 보면

```
   [내 컴퓨터]                              [구글 시트]
   작업폴더/data/intel.db   ──올려요──▶     팀 전체가 봅니다
   ↑ 진짜 데이터                             ↑ 사본 (보기용)
   여기에만 쌓여요                            여기서 고쳐도 소용없어요
```

- **`data/intel.db`가 진짜예요.** 모은 것과 분석 결과가 전부 여기 들어갑니다
- **시트는 사본이에요.** 보고 공유하는 용도라서, 시트에서 숫자를 고치셔도
  **다음에 올릴 때 덮어써집니다**
- 방향은 **DB → 시트 한쪽**이에요. 시트에 뭘 적으셔도 DB로 돌아오지 않습니다

### 왜 각자 DB를 갖나요?

한 사람이 서버를 관리해야 하는 구조를 피하려고요. 대신 이렇게 됩니다.

| | |
|---|---|
| **내가 모은 것** | 내 DB에만 있어요 |
| **팀원이 모은 것** | 그분 DB에 있어요 — 내 분석엔 잡히지 않습니다 |
| **합치려면** | 팀원 DB 파일을 받아서 "합쳐줘"라고 말씀하세요 (중복은 알아서 걸러 드려요) |
| **결과 공유** | 시트에 올리면 전원이 봅니다 |

### 중복 수집은 막아 드려요

내 DB에 없어도 **팀원이 이미 모았을 수 있어요.** 그래서 모으기 전에 시트 기록을 확인해서
"팀원이 3시간 전에 같은 걸 모았어요"라고 알려 드립니다.
(시트를 설정 안 하셨으면 이 확인은 건너뛰고 그냥 모아요.)

⚠️ 다만 **시트는 "끝난 수집"만 알아요.** 지금 팀원이 모으고 계신 건 잡히지 않으니,
큰 수집은 미리 말을 맞추시는 편이 좋습니다.

### 작업폴더가 뭔가요?

```
내가정한폴더/          ← 여기서 Claude를 엽니다
├── data/
│   └── intel.db      ← 데이터가 여기 쌓여요
└── output/
    └── *.pdf          ← 리포트가 여기 나와요
```

**스킬 파일(`~/.claude/skills/`)과 데이터 폴더는 다른 곳이에요.**
스킬은 한 번 설치하시면 끝이고, 작업폴더는 프로젝트마다 따로 두셔도 됩니다 —
폴더를 바꾸시면 데이터도 따로 쌓여요.

### 자주 있는 상황

| 이런 상황 | 이래서 그래요 |
|---|---|
| "분석할 데이터가 없다"고 해요 | 그 브랜드나 카테고리를 아직 안 모은 거예요. 먼저 모으셔야 합니다 |
| 팀원 리포트엔 있는데 제 것엔 없어요 | 각자 DB라서 그래요. DB를 받아서 합치시면 됩니다 |
| 시트에 안 올라가요 | §7 설정을 안 하셨거나 실패한 거예요. **모은 데이터는 무사합니다** — 다음에 올라가요 |
| 폴더를 옮겼더니 데이터가 없어요 | 데이터는 작업폴더 안에 있어요. `data/intel.db`를 같이 옮겨 주세요 |

## 7. 구글 시트로 보고 싶다면 (선택, 10분)

**안 하셔도 괜찮아요.** 안 하시면 "시트 미러가 밀렸다"는 안내만 나오고 나머지는 전부
정상 동작합니다. 설정하시면 모을 때마다 시트가 자동으로 갱신돼요.
**보는 용도**라서 시트에서 손으로 고치신 값은 다음에 덮어써집니다.

1. [Google Cloud Console](https://console.cloud.google.com)에서 프로젝트를 하나 만드세요
2. **API 및 서비스 → 라이브러리** → `Google Sheets API` 검색 → **사용 설정**
3. **IAM 및 관리자 → 서비스 계정 → 만들기** (역할은 안 주셔도 돼요) → 만든 계정 클릭 →
   **키 → 키 추가 → JSON** 다운로드
4. 받으신 키 파일을 이렇게 두세요
   ```bash
   mkdir -p ~/.config/intel
   mv ~/Downloads/<받은키>.json ~/.config/intel/service-account.json
   chmod 600 ~/.config/intel/service-account.json
   ```
5. 빈 스프레드시트를 만드시고([sheets.new](https://sheets.new)), **공유** 버튼으로
   키 파일 안의 `client_email` 주소(`...@....iam.gserviceaccount.com`)를 **편집자**로
   추가해 주세요
6. 스프레드시트 URL에서 ID를 복사하세요 — `.../spreadsheets/d/`**`이 부분`**`/edit`
7. Claude에게 **"구글 시트 미러 설정해줘, 스프레드시트 ID는 <복사한 ID>"** 라고
   말씀하시면 나머지를 해 드립니다 (`pip3 install gspread`가 한 번 필요해요)

`안내` 탭과 데이터 탭들이 생기면 성공이에요.
**키 파일은 어디에도 공유하지 말아 주세요.**

## 8. 잘 안 될 때

| 이럴 때 | 이렇게 해 보세요 |
|---|---|
| 스킬이 안 떠요 | 폴더가 `~/.claude/skills/commerce-intel/` 로 들어갔는지 확인하시고 **새 대화**를 열어 주세요. 요청에 "수집·정리·조사·분석" 같은 **할 일**이 들어 있어야 해요 (브랜드 이름만 말씀하시면 안 뜹니다) |
| 판매처를 덜 찾은 것 같아요 | **"○○도 파는데 확인해줘"** 라고 알려 주시면 돼요. 확실하지 않은 곳은 일부러 목록에만 두고 모으지 않습니다 |
| "데이터가 이상하다"며 멈췄어요 | 사이트가 구조를 바꿨다는 신호예요. **"어댑터 확인해줘"** 라고 하시면 무엇이 달라졌는지 찾아 드려요 |
| 모은 개수가 사이트 숫자보다 적어요 | 품절 상품이 빠졌을 수 있어요. **"품절 포함해서 다시 모아줘"** 라고 말씀해 주세요 |
| 예전 데이터를 준 것 같아요 | 재사용한 거예요. **"다시 조사해"** 라고 하시면 새로 모읍니다 |
| 랭킹 변화가 안 나와요 | 쌓인 게 없어서예요. 과거는 가져올 수 없어요 — **"계속 모아줘"** 로 시작해 두시면 다음부터 보실 수 있습니다 |
| 시트가 갱신이 안 돼요 | §7 설정 문제예요. **모아 둔 데이터는 멀쩡합니다** — 설정만 하시면 밀린 만큼 따라잡아요 |
| 지금 뭐가 쌓여 있는지 모르겠어요 | **"지금까지 모은 거 요약해줘"** 라고 말씀해 주세요 |

막히시면 대부분 **Claude에게 그대로 말씀하시는 게 가장 빨라요** —
스크립트를 직접 치실 일은 없습니다.
