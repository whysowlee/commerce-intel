# commerce-intel 스킬 — 사용 안내

무신사·29CM·브랜드 자사몰에서 **상품·랭킹 데이터를 모아 리포트로 만들어 주는 Claude 스킬**이다.
말로 시키면 알아서 모으고, 쌓아 두고, 브라우저로 열어 보는 HTML 리포트를 만든다.

---

## 1. 설치

폴더를 Claude가 읽는 위치에 옮기면 끝이다.

```bash
unzip commerce-intel-skills.zip

# 어디서나 쓰기
cp -r skills/* ~/.claude/skills/

# 특정 프로젝트에서만 쓰기
cp -r skills/* <프로젝트>/.claude/skills/
```

### 승인 프롬프트를 없애려면 (선택)

스킬이 스크립트를 돌릴 때마다 **"실행할까요?"가 뜬다.** 매번 누르기 번거로우면 아래를
`~/.claude/settings.json`(없으면 새로 만든다)의 `permissions`에 넣는다. 우리 스크립트
실행만 열고 **임의 명령은 그대로 물어본다** — 그게 이 방식이 안전한 이유다.

```json
{
  "permissions": {
    "allow": [
      "Bash(python3 ~/.claude/skills/commerce-intel/scripts/validate_data.py:*)",
      "Bash(python3 ~/.claude/skills/commerce-intel/scripts/eda.py:*)",
      "Bash(python3 ~/.claude/skills/commerce-intel/scripts/analyze.py:*)",
      "Bash(python3 ~/.claude/skills/commerce-intel/scripts/insight.py:*)",
      "Bash(python3 ~/.claude/skills/commerce-intel/scripts/sync_sheets.py:*)",
      "Bash(python3 ~/.claude/skills/commerce-intel/scripts/pdf_doc.py:*)",
      "Bash(python3 ~/.claude/skills/commerce-intel/scripts/diff_snapshots.py:*)",
      "Bash(python3 ~/.claude/skills/commerce-intel/scripts/group_variants.py:*)",
      "Bash(python3 ~/.claude/skills/commerce-intel/scripts/plan_sample.py:*)"
    ],
    "deny": [
      "Bash(python3 ~/.claude/skills/commerce-intel/scripts/intel_db.py:*)"
    ]
  }
}
```

- **`intel_db.py`는 일부러 deny다.** 정본 DB를 덮는 `merge`·`import-snapshots`가 들어
  있어서다. 이건 승인을 거치는 게 맞다(자주 쓰지도 않는다)
- 위는 **`~/.claude/skills/`에 설치했을 때** 기준이다. 다른 곳에 설치했으면 경로를
  그에 맞게 바꾼다
- 안 넣어도 동작에는 문제가 없다 — 승인만 매번 뜬다

설치되는 스킬은 이렇게 나뉜다 — **말은 그냥 하면 되고, 어느 단계로 갈지는 알아서 정해진다.**

| 스킬 | 하는 일 |
|---|---|
| `commerce-intel` | **여기로 말을 건다.** 요청을 읽고 아래 단계로 넘긴다 |
| `intel-collect` | 사이트에서 모은다 |
| `intel-store` | DB에 넣고 시트에 올린다 · 팀원 것과 합친다 |
| `intel-explore` | 분석 전에 데이터 상태를 본다 |
| `intel-insight` | 검증된 가설을 PDF로 낸다 |
| `platform-*` | 사이트별 수집 방법 (무신사·29CM·자사몰·W컨셉·그 외) |

**새 대화**를 열면 인식된다. Python 3.9 이상과 **패키지 하나**가 필요하다.

```bash
python3 -m pip install reportlab      # 리포트 PDF를 만드는 데 쓴다
```

Claude가 웹 요청을 보낼 수 있어야 하고, 브라우저 제어 도구(Playwright MCP 등)가 있으면 더 잘 된다.

## 2. 시작하기

데이터가 쌓일 폴더를 하나 정하고, 거기서 Claude를 연다.

```bash
mkdir -p ~/work/intel && cd ~/work/intel
```

### 팀에서 같이 쓸 때 (중요)

각자 자기 컴퓨터에 자기 데이터를 갖는다. 그래서 **두 가지만 지켜 달라.**

1. **랭킹 계속 모으기는 한 명만 한다.** 여러 명이 같은 랭킹을 각자 쌓으면 기록이
   사람마다 갈라져서 "지난주 대비 변화" 같은 걸 아무도 제대로 못 본다. 누가 돌릴지
   정해 두고, 나머지는 그 사람 결과를 받아 쓴다.
2. **같은 걸 여러 명이 동시에 모으지 않는다.** 사이트에 부담이 가고, 막히면 전원이
   못 쓰게 된다. 모으기 전에 팀에 한 번 물어보는 게 빠르다.

나중에 각자 모은 데이터를 합칠 수 있다 — `intel_db.py merge`.

첫 요청 때 필요한 준비는 스킬이 알아서 한다. 결과물은 이렇게 쌓인다.

```
~/work/intel/
├── data/        모아 온 데이터가 여기 쌓인다 (지우지 말 것 — 다음에 다시 안 모으는 근거다)
└── output/      리포트 PDF. 더블클릭하면 열린다 (휴대폰으로 보내도 된다)
```

## 3. 뭐라고 말하면 되나

**사이트 이름은 넣어도 되고 안 넣어도 된다.** 안 넣으면 스킬이 알아서 찾는다.

| 하고 싶은 것 | 이렇게 말한다 |
|---|---|
| 브랜드 상품 전부 정리 | "로우클래식 라인시트 수집해줘" · "무신사에서 인사일런스 상품 다 모아줘" |
| 여러 사이트 비교 | "인사일런스 파는 데 전부에서 라인시트로 정리해줘" · "무신사랑 29cm에서 비교해줘" |
| 시장 조사 | "여성 로우라이즈 데님 전수조사해줘" · "무신사 데님팬츠 시장 조사해줘" |
| 어디서 파는지 | "로우클래식 어디에 입점해 있어?" |
| 랭킹 쌓기 시작 | "29CM 여성슈즈 랭킹 지금 수집해줘" · "무신사 바지 랭킹 오후 11시까지 계속 모아줘" |
| 랭킹 변화 보기 | "지난 24시간 순위 크게 오른 상품 보여줘" |
| 자사몰 비교 | "인사일런스 자사몰이랑 무신사 비교해줘" |
| 분석 | "핏별 가격대 비교해줘" · "데님 가격이랑 반응 관계 분석해줘" |
| 경쟁사 비교 | "우리 브랜드랑 ○○ 비교해줘" |

### 사이트를 안 말하면 이렇게 된다

- **브랜드만 말하면** — 어디서 파는지 먼저 찾아서 **판매처 목록·규모·예상 소요를 보고**하고,
  확인된 판매처 **전부**를 모은다. 입점처는 정해진 사실이라 고르라고 묻지 않는다.
  (실제로 이렇게 나온다 — 인사일런스: 자사몰 · 무신사 남성/우먼 · 29CM 남성/우먼 · W컨셉 · 지그재그)
- **카테고리만 말하면** — 어느 사이트에 얼마나 있는지 **후보와 규모를 보여주고 고르게 한다.**
  상품군은 사실상 모든 사이트에 있어서 임의로 정하지 않는다.
- **사이트를 말하면** — 말한 곳만 모은다. 친절하게 더 붙이지 않는다.

### 안 뜨는 요청

"쿠팡에서 노트북 최저가 찾아줘"(개인 쇼핑), "이 바지 대신 사줘"(구매 대행),
"크롤러 짜는 법 알려줘"(일반 코딩 질문). 시장 조사 도구지 쇼핑 도구가 아니다.

### 모으는 것과 분석하는 것은 따로다

"모아줘"만 하면 모아서 쌓아 두고 끝난다. 며칠 뒤에 **"아까 모은 걸로 핏별 가격 비교해줘"** 라고만 해도 된다.
분석할 대상을 생략하면 **직전에 모은 주제를 이어서** 해석한다. 한 번에 둘 다 말하면 이어서 한다.

말하다가 범위를 바꿔도 된다 — **"무신사랑 바이모노만 수집해줘"**, **"자사몰도 추가해줘"**.

### 같은 걸 또 시키면 다시 안 모은다

최근에 모은 게 있으면 **모으는 걸 건너뛰고 "언제 것을 썼는지" 알려준다.**
가격·순위처럼 자주 바뀌는 값은 몇십 분~하루, 옷의 핏 같은 잘 안 변하는 값은 석 달 동안 재사용한다.

**꼭 새로 받고 싶으면 "다시 조사해" · "새로 받아" · "지금 수집해줘"** 라고 말하면 된다.

### 랭킹은 "지난달 것"을 못 가져온다

과거 순위를 파는 곳이 없다. **모으기 시작한 시점부터만** 쌓인다.
그래서 "지난달 변화"를 보려면 지난달에 모으기 시작했어야 한다.
**"○○ 랭킹 계속 모아줘"** 라고 하면 사이트 갱신 주기에 맞춰(무신사 30분·29CM 1시간)
자동으로 쌓기 시작한다. **"11시까지만"** 처럼 기한을 주면 그때 알아서 멈춘다.

## 4. 뭐가 나오나

`output/` 폴더에 **PDF 두 개**가 나온다. 휴대폰에서도 그대로 열리고 남에게 보내도 된다.

**인사이트 PDF** — 짧다. 3~6쪽. 매일 보는 것.

- **강한 주장 5개** — 다섯 관문을 전부 통과한 것만 싣는다
- **약한 단서 20개** — 통과하지 못한 것. 어느 관문을 왜 못 넘었는지, 어떻게 다시
  확인하는지가 같이 적혀 있다
- 항목마다 **판매전략 / 디자인 / 마케팅** 딱지가 붙어 있어 자기 것만 골라 읽으면 된다

**상세 PDF** — 길다. 근거를 볼 때 여는 것. 인사이트의 각 항목이 "상세 12쪽" 식으로
어디를 보면 되는지 알려준다.

### 강한 주장이 5개보다 적게 나올 수 있다

일부러 그렇게 만들었다. 관문을 통과한 게 3개면 3개만 낸다 — 빈자리를 약한 것으로
채우면 "강한 주장"이라는 말이 아무 뜻도 없어진다.

### 다섯 관문

1. **차이가 충분히 큰가** — 작은 차이는 발주 결정을 바꾸지 못한다
2. **표본이 충분한가** — 30건 미만은 쓰지 않는다
3. **우연이 아닌가** — 가설을 많이 만들면 우연히 그럴듯한 게 반드시 나온다. 그걸 보정한다
4. **쪼개도 유지되는가** — 전체에서 보이던 차이가 카테고리별로 나누면 뒤집히는 일이 있다
5. **다시 나오는가** — 데이터 절반으로 다시 확인해서 같은 방향이 나와야 한다

### 이렇게 나온다

> **[판매전략]** 플랫폼에서 lowclassic.com은 29CM보다 할인율이 낮다 (중앙값 0 대 18)
> *Cliff δ -0.67 · n=1,317 · p=0.000 · 홀드아웃 δ=-0.70*

숫자를 단정하지 않는다. **"할인을 줄여라"가 아니라 "이런 차이가 관측됐다"** 로 쓴다.
판단은 사람이 한다.

리포트를 보다가 더 궁금한 게 생기면 그냥 말하면 된다 — "이거 브랜드별로 나눠서 다시 봐줘".
다시 모으지 않고 새로 만들어 준다.

## 5. 이런 건 안 해준다

버그가 아니라 일부러 그렇게 만들었다. 틀린 숫자를 그럴듯하게 내놓는 것보다 낫다고 봤다.

- **화면에 없는 값은 만들어내지 않는다.** 후기 수로 판매량을 역산하는 식의 추정은 **요청해도 안 한다.**
  안 보이는 값은 리포트에 "미노출"로 찍힌다.
- **사이트가 막으면 멈춘다.** 우회하지 않고, 거기까지 모은 걸로 리포트를 내면서 중단 사실을 밝힌다.
- **상품 이름이 완전히 같을 때만 같은 상품으로 친다.** 비슷한 이름을 묶지 않는다 — 정가까지 똑같은
  다른 상품이 실제로 있었다. 안 묶인 건 **"이 사이트에만 있는 상품"** 이라는 정보다.
- **묻지 않고 상위 몇 개만 모으는 일은 없다.** 양이 많아도 다 모은다. 대신 **예상 소요를 먼저 알려주니**
  거기서 범위를 좁히면 된다.
- **로그인하지 않는다.** 로그인이 필요한 값이면 물어본다. **결제는 어떤 경우에도 하지 않는다.**
- **HTML 리포트를 만들지 않는다.** 산출물은 PDF뿐이다. 조건을 바꿔 가며 들여다보는
  대시보드는 없앴고, 대신 **조건을 바꿔 보는 일을 도구가 미리 다 해서** 살아남은 것만 싣는다.
- **W컨셉은 품절 정보를 못 가져온다.** 목록에 품절 상품을 아예 싣지 않는 구조라
  "품절 아님"으로 채우면 거짓말이 된다. 그래서 품절 칸을 비워 두고 그 사실을 밝힌다.
- **EQL·SSF는 "지금 봐줘"라고 할 때만 모은다.** 두 사이트는 자동 반복 수집을 허용하지
  않아서 랭킹을 계속 쌓아 두지 않는다. 랭킹 축적은 무신사·29CM에서 한다.

## 6. 구글 시트로 보고 싶다면 (선택, 10분)

**안 해도 된다.** 안 하면 "시트 미러가 밀렸다"는 안내만 나오고 나머지는 전부 정상이다.
설정하면 모을 때마다 시트가 자동으로 갱신된다. **보는 용도**라서, 시트에서 손으로 고친 값은 다음에 덮인다.

1. [Google Cloud Console](https://console.cloud.google.com) → 프로젝트 하나 만들기
2. **API 및 서비스 → 라이브러리** → `Google Sheets API` 검색 → **사용 설정**
3. **IAM 및 관리자 → 서비스 계정 → 만들기** (역할은 안 줘도 된다) → 만든 계정 클릭 →
   **키 → 키 추가 → JSON** 다운로드
4. 키 파일 두기
   ```bash
   mkdir -p ~/.config/intel
   mv ~/Downloads/<받은키>.json ~/.config/intel/service-account.json
   chmod 600 ~/.config/intel/service-account.json
   ```
5. 빈 스프레드시트를 만들고([sheets.new](https://sheets.new)), **공유** 버튼으로
   키 파일 안의 `client_email` 주소(`...@....iam.gserviceaccount.com`)를 **편집자**로 추가
6. 스프레드시트 URL에서 ID를 복사한다 — `.../spreadsheets/d/`**`이 부분`**`/edit`
7. Claude에게 **"구글 시트 미러 설정해줘, 스프레드시트 ID는 <복사한 ID>"** 라고 말하면 나머지를 해준다
   (`pip3 install gspread` 한 번이 필요하다)

`안내` 탭과 데이터 탭들이 생기면 성공이다. **키 파일은 어디에도 공유하지 말 것.**

## 7. 잘 안 될 때

| 이럴 때 | 이렇게 |
|---|---|
| 스킬이 안 뜬다 | 폴더가 `~/.claude/skills/commerce-intel/` 로 들어갔는지 확인하고 **새 대화**를 연다. 요청에 "수집·정리·조사·분석" 같은 **할 일**이 들어 있어야 한다 (브랜드 이름만 던지면 안 뜬다) |
| 판매처를 덜 찾은 것 같다 | **"○○도 파는데 확인해줘"** 라고 알려주면 된다. 확실하지 않은 곳은 일부러 목록에만 두고 안 모은다 |
| "데이터가 이상하다"며 멈췄다 | 사이트가 구조를 바꾼 신호다. **"어댑터 확인해줘"** 라고 하면 무엇이 달라졌는지 찾는다 |
| 모은 개수가 사이트 숫자보다 적다 | 품절 상품이 빠졌을 수 있다. **"품절 포함해서 다시 모아줘"** 라고 말한다 |
| 예전 데이터를 준 것 같다 | 재사용한 것이다. **"다시 조사해"** 라고 하면 새로 모은다 |
| 랭킹 변화가 안 나온다 | 쌓인 게 없어서다. 과거는 못 가져온다 — **"계속 모아줘"** 로 시작해 두면 다음부터 볼 수 있다 |
| 시트가 갱신이 안 된다 | §6 설정 문제다. **모아 둔 데이터는 멀쩡하다** — 설정만 하면 다음에 밀린 만큼 따라잡는다 |
| 지금 뭐가 쌓여 있는지 모르겠다 | **"지금까지 모은 거 요약해줘"** 라고 말한다 |

막히면 대부분 **Claude에게 그대로 말하는 게 가장 빠르다** — 스크립트를 직접 칠 일은 없다.
