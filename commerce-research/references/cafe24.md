# 자사몰(Cafe24) 어댑터

조사 시점 **2026-07-30**. 실측 스토어는 **인사일런스**(`insilence.co.kr`)와
**2000아카이브스**(`2000archives.com`) 두 곳이다.
"확인"은 그날 실제 응답으로 검증한 것, "미검증"은 확인하지 못한 것이다.
**미검증 항목을 사실처럼 쓰지 마라.**

이 어댑터는 **한 사이트가 아니라 Cafe24라는 엔진**을 다룬다. 무신사·29CM는 사이트가 하나씩이지만
자사몰은 브랜드마다 도메인이 다르고, **같은 Cafe24라도 스토어마다 스킨이 달라 URL 경로와
DOM이 다르다.** 그래서 이 문서의 규칙은 "경로를 외워라"가 아니라 **"사이트에서 찾아내라"**다.

## 지원 범위

**Cafe24 기반 자사몰만 지원한다.** 고도몰·임웹·Shopify·메이크샵 등 다른 엔진은 비범위다
(SPEC §3). 엔진 판별은 아래 §1로 하고, Cafe24가 아니면 **수집하지 말고 비범위임을 알린다.**

## 접근 정책

두 스토어 `robots.txt` 모두 `User-agent: *`에 아래를 `Disallow`한다 (2026-07-30 확인).
Cafe24가 스토어에 기본 배포하는 파일이라 대체로 같지만 **스토어마다 반드시 다시 읽어라.**

```
Disallow: /admin        /api        /exec/front/   ← Cafe24 내부 AJAX
Disallow: /member/      /myshop/    /protected/    ← 로그인 영역
Disallow: /skin-*/
Disallow: /board/*/modify.html  /reply.html  /write.html
Disallow: /*board*page=          ← 게시판 목록 페이지 넘김
Disallow: /*board*category_no=
Disallow: /*page_4=  /*page_6=    ← 상세 페이지 안 게시판(후기·Q&A) 페이지 넘김
```

**허용된다**: 상품 목록(`/product/*_list.html`), 상품 상세(`/product/detail.html`,
SEO 재작성 URL), 목록의 `&page=` 페이지네이션. 이 어댑터가 쓰는 경로는 전부 여기 안에 있다.

**금지된다 — 그리고 이것 때문에 후기를 수집하지 않는다**: `/*page_4=`가 막혀 있어
**상품 후기 게시판을 넘겨볼 수 없다.** `/exec/front/`(리뷰 더보기가 부르는 경로)도 막혀 있다.
SPEC §1의 "우회 없이 사이트가 밝힌 정책 안에서 동작한다"에 따라 **우회하지 않는다.**

`Claude-User`를 따로 지정한 스토어는 없었다 — `*` 규칙이 적용된다.
403·캡차·봇 챌린지는 없었고 전 페이지 200이었다.

## §0. 자사몰에서 나오지 않는 값 (2026-07-30 실측, 사용자 결정)

**후기 수 · 평점 · 좋아요 · 조회수 · 누적판매는 수집하지 않는다. 전부 `null`이다.**

| 값 | 왜 없나 |
|---|---|
| `review_count` `rating` | 스토어마다 다르지만 **어느 쪽도 쓸 수 없다.** 2000아카이브스는 Cafe24 기본 후기 영역이 상세에 렌더되지만(`게시물이 없습니다`) 개수를 세려면 `page_4=`로 넘겨야 하고 **robots.txt가 막는다**. 인사일런스는 외부 위젯(크리마)을 쓰는데 상세에 위젯이 **마운트조차 되지 않고**(REVIEWS 탭에 연관 상품만 있다) Cafe24 기본 후기 게시판(`board_no=4`)은 "사용할 수 없습니다"로 비활성이다 |
| `like_count` | 두 스토어 모두 상품에 좋아요·찜 카운터가 없다 |
| `view_count` `viewers_now` `buyers_now` | 노출 없음 |
| `purchase_count` | 노출 없음 |

**리포트에 이 사실을 밝힌다.** 자사몰은 스토리1의 **`같은 상품 반응 강도 비교`(축 ②)에서
빠진다** — 비교할 지표가 없다. **`품목별 입점 차이`(축 ①)와 `가격·할인 포지셔닝`(축 ③)은
그대로 성립한다.** 자사몰의 값어치는 반응이 아니라 **"어디에 뭘 냈고 얼마에 파는가"**다.

크리마 위젯 API를 뜯어 후기 수를 얻는 방법은 **쓰지 않기로 했다**(2026-07-30 사용자 결정) —
화면에 없는 값이고, 위젯 업체가 스토어마다 달라 일반화되지 않는다.

## 1. 브랜드명 → 도메인 찾기, 그리고 Cafe24인지 확인

사용자는 보통 도메인이 아니라 **브랜드 이름**을 말한다("인사일런스 자사몰도 같이 봐줘").
도메인을 **지어내지 마라.** 절차는 이렇다.

1. **웹 검색으로 공식 자사몰 도메인 후보를 찾는다.** 브랜드명 + `공식몰`/`official store` 등
2. **후보를 열어 브랜드가 맞는지 확인한다** — 페이지 타이틀·상단 로고·푸터의 상호가
   찾는 브랜드와 일치하는지 본다. 애매하면 **사용자에게 후보를 제시하고 고르게 한다**
   (동명 브랜드가 흔하다 — E-IN-2와 같은 처리)
3. **Cafe24인지 확인한다.** 페이지에서 아래 신호를 찾는다 (하나라도 걸리면 Cafe24):

```js
/cafe24|ecimg\.cafe24|cfa-js\.cafe24|app4you\.cafe24/i.test(document.documentElement.outerHTML)
```

   실측: 인사일런스는 `cfa-js.cafe24.com`, 2000아카이브스는 `cfa-js.cafe24.com` +
   `app4you.cafe24.com`이 잡힌다. Cafe24가 아니면 **비범위임을 알리고 수집하지 않는다.**

4. 확정한 도메인을 `meta.site`에 담는다 — **값은 도메인 문자열**이다(`insilence.co.kr`).
   `meta.notes`에 어떻게 찾았는지(검색어·확인 근거)를 남긴다

## 2. URL 패턴 — 스토어마다 다르다 (확인)

**경로를 하드코딩하지 마라.** Cafe24는 스킨이 목록 페이지 파일명을 정하고, 상품 URL 형식도
스토어 설정에 따라 두 가지가 있다.

| | 인사일런스 | 2000아카이브스 |
|---|---|---|
| 목록 | `/product/man_list.html?cate_no=337`<br>`/product/woman_list.html?cate_no=348`<br>`/product/outlet_list.html?cate_no=685` | `/product/list.html?cate_no=42` |
| `/product/list.html` | **404** | 200 |
| 상품 | `/product/detail.html?product_no=7180` | `/product/{슬러그}/2774/category/42/display/1/` |
| 페이지당 | 24개 | 24개(추정 — 실측 카테고리가 8개짜리뿐이라 미검증) |
| 통화 표기 | `KRW 149,000` | `139,000원` |

- **목록 URL은 네비게이션 링크에서 얻는다** — `a[href*="cate_no"]`를 긁으면 라벨과 경로가
  같이 나온다(§3)
- **`product_id`는 두 형식 모두에서 뽑아야 한다**:
  `?product_no=(\d+)` 또는 SEO 형식의 `/product/[^/]+/(\d+)/`
- 상세는 어느 스토어든 **`/product/detail.html?product_no={id}`로도 열린다** (인사일런스 확인).
  2000아카이브스에서도 열리는지는 **미검증** — 목록에서 얻은 링크를 그대로 쓰는 편이 안전하다

## 3. 전량 수집 — 카테고리를 전부 돌고 상품번호로 중복 제거 (확인)

**`ALL` 카테고리 하나만 돌면 안 된다.** 인사일런스 실측(2026-07-30):

| 카테고리 | 상품 수 |
|---|---|
| 남성복 `ALL` (`man_list?cate_no=337`) | 222 |
| 여성복 `ALL` (`woman_list?cate_no=348`) | 206 |
| **남·여 `ALL` 합집합** | **428** |
| `SEASON OFF` (`outlet_list?cate_no=685`) | 349 — **이 중 127건이 `ALL`에 없다** |
| **전체 합집합** | **555** |

**`ALL`만 쓰면 127건(23%)을 놓친다.** 시즌오프 상품이 `ALL` 트리에서 빠져 있기 때문이다.
"ALL"이라는 이름을 믿지 마라 — **그 스토어의 한 트리 안에서만 전부**라는 뜻이다.

**Cafe24에는 스토어 전체를 주는 루트 카테고리가 없다** — `cate_no=1`, `/product/list.html`은
인사일런스에서 404다(확인).

### 절차

1. 홈에서 네비게이션의 카테고리를 전부 긁는다 — `a[href*="cate_no"]`에서 `(라벨, 경로)` 수집.
   중복 경로는 접는다
2. **상품 목록이 아닌 것을 뺀다** — 인사일런스의 `lookbook_list`·`contents_list`처럼
   컨텐츠용 경로가 섞여 있다. 상품 목록인지는 열어서 `ul.prdList > li`가 나오는지로 판단한다
3. 각 카테고리를 `&page=`로 끝까지 순회한다(아래 종료 판정)
4. **`product_id`로 중복을 제거해 합집합을 만든다.** 한 상품이 여러 카테고리에 들어 있다
5. `category`에는 **그 상품을 처음 만난 카테고리 라벨**을 담는다. 여러 곳에 있으면
   `meta.notes`에 그 사실을 남긴다

### 페이지 순회와 종료 판정 (확인)

- 페이지네이션은 **`&page=N`**이다. 무한 스크롤이 아니다
- **범위를 넘는 페이지는 에러가 아니라 빈 목록을 준다** — `page=99`가 200에 0건이었다
- **종료 판정은 `다음` 버튼이다** — `.xans-product-normalpaging .btnNext a`의 `href`가
  `#none`이면 마지막 페이지다. 실측: `cate_no=337`은 10페이지에서 6건 + `#none`
- **함정: 페이지 번호 목록은 5개씩만 보이는 슬라이딩 창이다.** 1페이지에서 `1 2 3 4 5`만
  보인다고 5페이지가 끝이 아니다(실제는 10페이지). 번호 링크의 최대값을 끝으로 믿지 마라
- **요령: 큰 페이지 번호를 한 번 던지면 마지막 페이지를 알려준다.** `page=999`를 요청하면
  본문은 0건이지만 페이지네이션 위젯이 **실제 마지막 페이지까지의 창**을 그려준다
  (`cate_no=337` → `6 7 8 9 10`, 다음=`#none`). 순회 전에 규모를 가늠할 때 쓴다

### 완전성 근거 — 화면 총계가 없다

**Cafe24 목록에는 "총 N개"가 없다** (두 스토어 확인). 그러므로:

- **`source_total`은 `null`로 둔다.** 수집 건수를 넣지 마라 — 자기 자신과 비교하는
  순환 검증이 된다(E-SR-10)
- 완전성 근거는 **"네비게이션의 모든 상품 카테고리를 소진했고, 각 카테고리가 `btnNext=#none`에
  도달했다"**이다. 29CM 브랜드 목록의 `hasNext=false` 근거와 같은 성격이다(SPEC §4 스토리1)
- **어느 카테고리에도 걸려 있지 않은 상품은 구조적으로 놓친다.** 총계가 없어 검출할 방법이
  없다는 사실을 `meta.notes`에 남긴다

## 4. 품절 — 목록엔 표시가 없고 상세 JSON-LD에만 있다 (확인)

**Cafe24 목록은 품절 상품을 포함하지만 배지를 달지 않는다.** 인사일런스 192개를 스캔해
목록 HTML에서 `품절`/`sold out` 문자열 **0건**이었는데, 그중 `product_no=7489`는 상세에서
**「품절」 버튼**이 뜨는 품절 상품이었다.

**이것은 무신사·29CM와 또 다른 세 번째 패턴이다:**

| 사이트 | 목록의 품절 |
|---|---|
| 무신사 | 기본 **제외** — `&isSoldOut=true`를 줘야 포함 |
| 29CM | 기본 **포함** + `품절` 배지 |
| **자사몰(Cafe24)** | 기본 **포함** + **배지 없음** — 상세를 열어야 안다 |

**플랫폼을 비교할 때 필터를 맞춰라**(SPEC §4·29CM 어댑터와 같은 경고). 자사몰은 품절이
섞여 들어오므로 무신사를 품절 포함(`&isSoldOut=true`)으로 맞춰야 비교가 성립한다.

### 판정 규칙 (실측)

상세 JSON-LD의 `offers`는 **사이즈(옵션)별 배열**이다. 옵션마다 `availability`가 다르다.

```
offers: []                                → 품절   (전 옵션 재고 없음 — 화면에 「품절」 버튼)
offers 중 하나라도 "InStock"              → 판매중 (일부 사이즈만 품절인 경우)
offers 전부 "OutOfStock"                  → 품절
```

실측 14건: `InStock`만 5건, `OutOfStock,InStock` 혼재 5건, `offers` 빈 배열 4건.
**혼재는 판매중이다** — 일부 사이즈 품절을 품절로 세면 안 된다.

## 5. 필드 매핑

출처가 두 개다 — **목록 DOM**과 **상세 JSON-LD**. 스토리1은 **상품당 상세 1회가 필요하다**
(품절과 판매가를 상세에서 확정한다). 상세 비용은 무신사·29CM와 같은 수준이라
스토리1 상한 3,000개(≈60분)의 근거가 그대로 적용된다.

| 계약 | 목록 DOM | 상세 JSON-LD |
|---|---|---|
| `product_id` | `?product_no=(\d+)` 또는 `/product/[^/]+/(\d+)/` | 〃 |
| `name` | `a.name` 등 스킨별 — **JSON-LD를 정본으로 쓴다** | `name` |
| `url` | 목록의 상품 링크(절대 URL로) | `offers[].url` |
| `image_url` | `.thumb img` | `image[0]` |
| `brand` | — | `brand.name` (`INSILENCE`, `2000Archives`) |
| `category` | **순회한 카테고리 라벨**(§3) | JSON-LD엔 없다 |
| `price_original` | 정가 — 아래 함정 | 없다 |
| `price_sale` | 판매가 — 아래 함정 | **`offers[].price`** ← 정본 |
| `discount_rate` | `10%`처럼 목록에 찍힌다. 없으면 정가·판매가로 계산 | 없다 |
| `sold_out` | **알 수 없다**(§4) | `offers`의 `availability`(§4) |
| `review_count` `rating` `like_count` `view_count` `purchase_count` | `null` (§0) | `null` |
| `viewers_now` `buyers_now` | `null` | `null` |

### 함정 — 가격 클래스 이름이 뒤집혀 있다 (실측)

인사일런스 목록의 렌더 후 DOM:

```html
<div class="sale_price custom">    <span>KRW 166,000</span></div>  ← 실제로는 정가
<div class="original_price custom"><span>KRW 149,000</span></div>  ← 실제로는 판매가
```

**클래스 이름을 믿으면 정가와 판매가가 뒤집힌다.** 서버 HTML 쪽 `.real_contents`에는
라벨이 붙어 있어 정확하다:

```
소비자가 : KRW 166,000   ← price_original
판매가   : KRW 149,000   ← price_sale
```

- **`price_sale`은 상세 JSON-LD `offers[].price`로 확정하라** — 두 스토어에서 화면
  판매가와 일치했다(인사일런스 149,000 / 2000아카이브스 139,000). 이게 가장 안전하다
- `price_original`은 목록에서 얻는다. **라벨(`소비자가`)이 있는 스토어와 없는 스토어가 있다** —
  2000아카이브스는 라벨 없이 `72,000원`(취소선) · `39,600원 45%`로만 나온다.
  라벨이 없으면 **취소선이 걸린 값이 정가**이고, 값이 하나뿐이면 **정가 = 판매가**다
- **통화 표기가 스토어마다 다르다** — `KRW 149,000` / `139,000원`. 숫자만 뽑아라

### 함정 — 목록의 가격 박스는 JS가 채운다

`.custom_price_wrap`은 **서버 HTML에서 비어 있고** 브라우저에서 JS가 채운다.
HTTP로 HTML만 받아 파싱하면 가격이 빈 문자열로 나온다(실측). **브라우저로 렌더한 뒤 읽어라**
— 또는 서버 HTML에도 있는 `.real_contents`(라벨 있는 쪽)를 쓴다.

### 쿠폰적용가는 해당 없다

무신사(`finalPrice`)·29CM(`displayPrice`)는 판매가가 **전 회원 공통 쿠폰적용가**였다.
자사몰 두 곳에서는 상품 단위 쿠폰 자동적용 표기를 찾지 못했다 — JSON-LD `offers.price`가
화면 판매가와 그대로 일치한다. **쿠폰 배지가 붙은 스토어는 미검증**이므로,
그런 스토어를 만나면 화면 판매가와 `offers.price`를 대조해 확인하고 `meta.notes`에 남겨라.

## 6. 리뷰

**수집하지 않는다.** §0과 §접근 정책 참조 — robots.txt가 후기 게시판 페이지 넘김을 막고,
스토어에 따라 외부 위젯이라 화면에 개수 자체가 없다.

## 무신사·29CM와 다른 점 정리

| | 무신사 | 29CM | **자사몰(Cafe24)** |
|---|---|---|---|
| 사이트 수 | 1 | 1 | **브랜드마다 다름 — 도메인을 찾아야 한다** |
| 목록 경로 | 고정 | 고정 | **스토어 스킨마다 다름** |
| 화면 총계 | 있다 | 있다(카테고리·브랜드) | **없다 → `source_total`은 `null`** |
| 전량 경로 | 브랜드 전 상품 1개 | 브랜드 페이지 1개 | **카테고리 전부 순회 + 중복 제거** |
| 목록의 품절 | 기본 제외 | 포함 + 배지 | **포함 + 배지 없음(상세로 판정)** |
| 후기·평점 | 있다 | 있다 | **없다(수집 안 함)** |
| 좋아요 | 있다 | 있다(축약 표기) | **없다** |
| 조회수 | 구간 표기 | 없다 | **없다** |
| 페이지 크기 | 60 | 50 | **24** |

### 스토리1 멀티 플랫폼에서 주의할 것

- **품절 필터를 맞춰라.** 자사몰은 품절 포함이므로 무신사도 `&isSoldOut=true`로 맞춘다.
  안 맞추면 "자사몰 단독 입점"이 실제보다 부풀어 오른다(29CM 실측에서 83건 → 0건이 된 전례)
- **반응 강도 비교(축 ②)에서 자사몰을 빼고, 뺀 사실을 각주로 밝힌다**
- 상품명 매칭은 다른 플랫폼과 **같은 규칙**(정규화 완전일치)을 쓴다. 자사몰이라고
  느슨하게 하지 않는다 — 추정 매칭 금지는 플랫폼과 무관하다(SPEC §3)

## 런타임에 직접 확인할 것

- **2000아카이브스의 페이지 크기** — 실측 카테고리가 8건짜리뿐이라 24개인지 미검증
- **후기가 실제로 있는 스토어의 상세 화면** — 두 실측 스토어 모두 후기 0건이라
  "첫 화면에 몇 개가 렌더되는지"를 재보지 못했다. 어차피 수집하지 않지만,
  나중에 정책이 바뀌면 여기부터 다시 재야 한다
- **쿠폰을 자동 적용하는 스토어의 판매가** — 위 "쿠폰적용가는 해당 없다" 참조
- **SEO 재작성 URL 스토어에서 `/product/detail.html?product_no=`가 열리는지**
- **모바일 전용 도메인(`m.` 서브도메인)을 쓰는 스토어** — 두 실측 스토어는 반응형이라
  단일 도메인이었다
